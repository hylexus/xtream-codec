## 消息结构

| 标识位         | 消息头    | 消息体               | 校验码   | 标识位         |
|-------------|--------|-------------------|-------|-------------|
| 1byte(0x7e) | 16byte | 不同消息 ID 有不同格式 			 | 1byte | 1byte(0x7e) |

### 消息头

- `非分包消息` 的消息头长度为 `17字节`
- `分包消息` 的消息头长度为 `21字节`

消息头的结构如下所示：

```sh
消息ID[0-2)	消息体属性[2-4)	协议版本号[4]   终端手机号[5-15)	消息流水号[15-17)	消息包封装项[17-21)

byte[0-2) 	消息ID word(16)
byte[2-4) 	消息体属性 word(16)
		bit[0-10)	消息体长度
		bit[10-13)	数据加密方式
						此三位都为 0,表示消息体不加密
						第 10 位为 1,表示消息体经过 RSA 算法加密
						其它保留
		bit[13]		分包
						1: 消息体卫长消息,进行分包发送处理,具体分包信息由消息包封装项决定
						0: 则消息头中无消息包封装项字段
		bit[14]	    版本标识
		bit[15]	保留
byte[4]     协议版本号
byte[5-15) 	终端手机号或设备ID bcd[10]
		根据安装后终端自身的手机号转换
		手机号不足12 位,则在前面补 0
byte[15-17) 	消息流水号 word(16)
		按发送顺序从 0 开始循环累加
byte[17-21) 	消息包封装项
        如果消息体属性中相关标识位确定消息分包处理,则该项有内容
		否则无该项
		byte[0-2)	消息包总数(word(16)) 该消息分包后得总包数
		byte[2-4)	包序号(word(16))  从 1 开始
```

### 消息体

JT/T 808—2019 的位置汇报消息（`0x0200`）先携带 28 字节的基本位置数据，后面可跟随若干附加项。下表按本项目示例的属性顺序列出基本数据。

| 示例属性 | 含义 | 编码 |
| --- | --- | --- |
| `alarmFlag` | 报警标志位 | `DWORD`（4 字节） |
| `status` | 终端和定位状态 | `DWORD`（4 字节） |
| `latitude` | 纬度 | `DWORD`（4 字节） |
| `longitude` | 经度 | `DWORD`（4 字节） |
| `altitude` | 高程 | `WORD`（2 字节） |
| `speed` | 速度 | `WORD`（2 字节） |
| `direction` | 方向 | `WORD`（2 字节） |
| `time` | 上报时间 | `BCD[6]`，解码为 `yyMMddHHmmss` 字符串 |

每个附加项先读 1 字节的 `id`，再读 1 字节的 `contentLength`，最后按该长度读取 `content`。示例把内容保留为 `byte[]`。扁平化示例用消息体长度减去 28，得到附加项列表占用的字节数。

字段取值、单位和附加项 ID 的含义见 JT/T 808—2019 的位置汇报一节。
