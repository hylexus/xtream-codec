# Design

## Context

builtin.messages 的子包使用 @NullMarked。条件字段包含时间、装箱数值、字符串、集合和 record 组件；部分版本合一实体也会省略引用字段。工作区已有三个 2019 模型的部分可空标注，需保持并补齐访问器。

## Goals / Non-Goals

以实际省略语义表达引用类型的空值，不将所有尚未初始化的必要字段统一标为可空，不把基本类型改为包装类。

## Decisions

- 使用 org.jspecify.annotations.Nullable，紧邻字段类型、getter 返回类型和 setter 参数类型；数组注解放在数组维度前，表示数组引用可空。
- condition/conditions 仅控制线格式中的存在性；引用类型会保留 null，基本类型仍保留默认值。重复版本注解合并考虑，全部版本都存在的字段不因长度变化而标为可空。
- 同步已有可空字段的字段及访问器；对已有测试或明确编解码行为支持的省略参数、集合和附件外部元数据补齐契约。
- 利用已有条件字段、空集合及多版本回归测试验证运行行为，不新增仅重复注解声明的单元测试。
- 0102 合一实体的格式化 getter 同步返回可空值，字段缺省时直接返回 null；将原先记录空指针行为的两个旧版本断言更新为 assertNull。

## Risks / Trade-offs

- 将必要字段误标为可空 → 按条件、版本、已有断言和编解码器逐项核对。
- 改变 fluent setter 返回值语义 → 只标参数，返回实体自身保持非空。
- 数组与泛型类型注解位置混淆 → 只标容器引用，不标集合元素可空。
