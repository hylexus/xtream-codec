# Proposal

## Why

JT/T 808 内置请求消息中的两个 2011 独立类缺少单元测试，现有测试还存在对象自身比较、重复解码、参数标识未断言和条件分支未覆盖的问题，需要提高编解码回归验证的有效性。

## What Changes

- 为 `BuiltinMessage0100V2011`、`BuiltinMessage0102V2011` 增加独立的编码和解码测试。
- 核对 `request` 包的现有测试，修正无效断言，增加固定报文验证、完整字段断言及关键条件分支测试。
- 复用现有测试基类和 JUnit，运行请求包回归测试及相关检查。
- 修复固定报文测试暴露的两个既有缺陷：字段顺序未使用当前版本的注解，以及 U32 参数 ID 编码溢出，并补充核心模块回归测试。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

无。本次补齐测试并修复实现与现有注解及 U32 语义不一致的问题，不新增规格要求，设置 `skip_specs: true`。

## Impact

变更涉及 JT/T 808 模块的请求消息单元测试、核心模块的字段顺序和 U32 字典键编码及其回归测试，不引入依赖或公共 API 变更。2019 版 `0702AllInOne` 的字段排列将恢复为注解声明的协议顺序。
