# Design

## Context

请求消息测试继承 `BaseCodecTest`，已支持显式指定消息 ID、协议版本，以及固定十六进制报文的编解码。2011 与 2013 的报文头无法直接区分，涉及版本选择的解码需显式传入 2011。动机见 `proposal.md`。

## Goals / Non-Goals

以固定报文和完整字段断言发现编码、解码或版本选择的单向回归，覆盖已有模型的关键条件分支；按用户追加授权，最小修复已复现的字段顺序和 U32 键溢出缺陷，保持公共 API 不变。

## Decisions

- 新增的两个独立类测试使用明确的消息 ID 和 2011 协议，验证编码报文及固定报文解码，覆盖 GBK 文本、定长字段和鉴权码转义。
- 四个 AllInOne 测试用固定报文替代重复解码，分别检查编码输出和固定输入的字段；修正自身比较、源对象空值断言以及遗漏字段。
- 参数应答验证参数 ID、长度、顺序和值，并覆盖 TLV 未知参数；位置消息增加类型为零的条件字段用例，多媒体拍摄应答增加失败和空列表用例。
- 保留已有固定报文测试，补充发现的集合大小、末项时间等漏验字段，并确保直接解码请求的测试释放引用计数缓冲区。
- 字段顺序由已按版本筛选的 `XtreamField` 决定，避免重新扫描字段时错误选取第一个重复注解。U32 字典键已在构造时检查取值范围，写入时保留低 32 位。核心回归测试覆盖显式版本、默认版本和 U32 有符号边界及最大值。

## Risks / Trade-offs

- 固定报文录入错误 → 按字段宽度、GBK 编码、BCD 时间、异或校验和转义规则独立计算，并运行已有测试基准及新增断言。
- 测试数量无法代表完整协议覆盖 → 本次聚焦已发现的测试缺陷和现有模型分支，不扩展协议实现。
- 顺序修复涉及共享元数据 → 运行核心模块及 JT808 模块的完整测试，确认单版本模型及重复注解选择不受影响。
