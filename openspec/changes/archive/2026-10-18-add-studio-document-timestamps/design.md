# Design

## Context

动机见 `proposal.md`。`WorkspaceData.Entry` 已有 `updatedAt`，服务在创建、更新和导入时生成，列表响应也保留该字段。文件和 SQLite 均将完整条目保存为 JSON，因此新增可空属性不需要新表。前端目录索引含完整元数据，编辑器标签只保存文档身份及基线。

## Goals / Non-Goals

**Goals:** 在既有时间合同上补充创建时间并提供查看入口，兼容无此字段的历史存储和本地草稿。

**Non-Goals:** 用户、归属、权限、审计历史、时间排序和未保存草稿的本地创建时间不在本次范围。

## Decisions

1. 在 Entry 中增加可空 `Long createdAt`。创建时只读取一次服务器时钟供两种时间共用，更新保留旧 createdAt，最后更新时间沿用现有成功提交规则。保留原 Java 构造方法并将旧调用视为未知创建时间，避免影响现有宿主或自定义存储源码。
2. 旧 JSON 缺失字段自然读取为 null，保持格式版本 1；不批量重写或从 updatedAt 推测创建时间。与记录一个近似日期相比，“未记录”准确表达已有数据限制。
3. 导入继续建立新身份并重置版本及更新时间，创建时间也取此次导入时间。导出保留原有时间字段。单个文档导入为未保存副本，其时间以首次服务器保存为准。
4. 前端 WorkspaceEntry 增加可选 createdAt，以兼容旧接口及测试数据。当前报文信息使用已有目录元数据，保存后的 refresh 更新展示，不把时间放进文档内容、保存指纹或草稿格式。
5. 文档工具栏的“…”菜单提供“报文信息”入口，打开对话框列出两种时间；目录名称的原生提示增加同样信息。窄屏继续可打开信息。未保存、未知创建时间及未获取服务器元数据分别展示明确状态。
6. 移除底部状态栏，将工作区条目数及离线状态放到左侧目录标题旁，保存快捷键放到保存按钮的悬浮提示。关联服务器的版本继续由文档工具栏表达，未保存更改继续由报文标签的圆点表达；工具栏不增加常驻控件。

## Risks / Trade-offs

- 旧记录没有可靠创建时间 → 保持 null 并展示“未记录”，更新不补造历史。
- 列表元数据暂不可获取 → 显示“服务器时间不可用”，不把未知误报为尚未保存。
- 系统时钟精度与调整 → 沿用服务器 Unix 毫秒语义，不保证连续写入的时间严格递增，版本号继续负责并发控制。
- 旧服务不识别新增 JSON 属性 → 部署应使用更新后的后端读取新增记录；升级不清理旧数据。

## Migration Plan

升级后直接读取已有文件或 SQLite；无需数据迁移命令。历史记录的未知时间在后续更新时继续保留，新增及导入记录开始记录创建时间。运行两种存储的时间合同测试、UI 检查与浏览器展示验证，保留变更等待归档。
