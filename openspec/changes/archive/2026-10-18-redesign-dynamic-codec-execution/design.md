# Design

## Context

动机及范围见 proposal.md。行为基线是前序变更 `add-dynamic-binary-codec-and-debugger` 的三份规格及当前测试；本变更的两份 delta 明确补充或替换相应合同。前序尚未归档，不能假定 dynamic-binary-codec 已存在主规格，也不在本轮自动归档它。

当前 `DynamicPlan.Field` 同时保存原始 DSL 和部分执行配置；`DynamicExecution` 通过字符串路径 Map 管理值，并让编码走生成解码结果的公共流程。普通字段检查条件，子节点却直接进入类型分派。编码 byteScalar 后重新解码，集合和结构重新创建输出树。base 已提供 `XtreamExpressionEngine`、`XtreamExpression`、`XtreamEvaluationContext` 及注册表，但没有字段依赖提取、统一数值转换或沙箱合同。

评审已通过当前编译产物复现：choice 分支条件为假仍消费内容；缺少必需字符串泄漏 NPE；padding 数组在 List.copyOf 时泄漏 NPE。评审时已有动态测试 115 项、服务测试 5 项、HTTP 测试 2 项通过，这说明需要增加组合行为测试，而非仅把旧测试跑绿。

## Goals / Non-Goals

**Goals:**

- 每个执行节点的配置、依赖和状态生命周期可单独理解；增加节点不需要理解全局路径 Map 的恢复时机。
- 保留 schemaVersion 1 的已有 JSON 和 Java 使用入口；新增表达式形式以兼容重载接入。
- 通过完整节点语义和可复用计划减少热路径工作，同时保持位序、版本、长度、值表示和 Trace 合同。

**Non-Goals:**

- 不建立通用解释器框架、优化 pass 管线、事件总线、ThreadLocal 缓存或对象池；内部扩展只围绕已有 DSL。
- 不给每个整数宽度建类，不生成字节码，不暴露内部节点 SPI，不承诺不同表达式引擎算术完全等价。
- 不借此改造旧注解表达式工厂、整个 base 上下文实现或前端架构。

## Decisions

### 1. 编译阶段产出独立执行模型

编译按版本选择、符号登记及引用解析、布局与边界校验、执行节点构建的顺序完成。沿用现有可定位校验，新增表达式依赖与回填可用性分析。原始 schema 留在 DynamicPlan.schema() 用于交换和诊断，不作为执行配置读取来源。

内部节点按语义分组：整数/浮点、字节标量、原始位串/对齐、结构、数组、条目集合、choice、派生。具体名称在实现时保持简洁；可以使用 sealed 类型加 record 配置，不引入访问者和工厂的多层组合。一个整数节点包含符号、位宽、字节序和位序；一个字节节点包含值转换器、已解析 Charset、填充配置和边界。编码器及解码器各自穷尽分派内部节点类型。

长度采用互斥的内部类型：固定、引用、前缀、剩余、表达式；默认值、条件常量、位段掩码、扩展实例和条目布局在编译时确定。Charset 可共享，CharsetEncoder/Decoder 属于单次调用，不能写入并发计划。

不采用继续扩充一个含大量 nullable 属性的计划 record：那会继续让运行时判断哪些配置属于当前节点。

### 2. 显式执行帧与值生命周期

每个结构布局分配稳定的字段位置；引用由所在作用域及位置表达。内部可用 `(parentDepth, slot, memberSlots)` 描述同层、外层及已完成结构的限定引用。字符串路径仅用于诊断；编译期继续使用 Map 建立符号表。

每次调用建立独立执行帧。集合元素和分支使用各自局部帧，结束后直接退出，不通过改写全局 Map 再恢复旧值。父层引用指向父帧；禁止把集合元素局部值暴露给下一元素。已完成具名 struct 的被引用成员保留至所属帧结束。

slot 明确区分未执行、条件跳过、等待回填、已完成的 null 和已完成的值。可以使用私有哨兵或紧凑状态数组，不为每次字段访问创建包装对象。编码只保留后续引用及回填需要的值；解码结果树与内部引用存储分别承担返回值和执行依赖职责。

### 3. 编码和解码各有主流程，所有节点经过共同的语义阶段

编码负责输入检查、写入、回填与必要值保留；解码负责读取、返回值树和成功后提交 readerIndex。移除编码返回 DynamicDecodeResult 的设计，不通过继承强制两个方向生成相同结果。

两方向的节点入口都遵守：检查深度/资源 → 检查条件 → 进入作用域及 Trace（若启用）→ 执行内容 → 校验边界/进度 → 完成值和回填 → 结束 Trace。共享边界计算、条件求值及异常定位等纯逻辑；允许方向主流程有少量直观重复，不通过方向标志或大型模板基类重新合并。

普通字段、item 和 variant 不得绕过条件阶段。条件 false 不访问输入值、不执行扩展、不消费内容。具名字段及其 choice 分支 false 时省略对应键；数组 false 元素仍触发原有零进度保护；TLV 值 false 仍必须满足声明长度。padding/align 执行完成后是 null 业务值而非“跳过”，列表和条目快照必须允许这种 null。

错误定位在最靠近失败节点的入口补充，保留 cause，不捕获 Error，也不把程序缺陷一概转换成“输入无效”。常见必需值缺失和类型不匹配显式检查，避免依靠 Objects.requireNonNull 处理用户输入。

### 4. 回填动作绑定到布局边界

编译器将 computedLengthOf 区间解析为起止节点位置和回填目标，并把起止动作挂到所属布局边界。每个执行帧持有自己的回填 offset/start 状态；运行时不逐字段扫描全部待回填项或比较路径字符串。

区间边界动作在条件跳过时仍执行，长度只统计实际写入位数。长度字段被跳过则不登记回填；多个回填共享边界时分别完成。编码结束必须没有未完成的活动回填。

等待回填的字段不提供普通整数值。编译时拒绝在回填完成前读取它的条件、表达式或派生依赖；已有 length.ref 指向相应回填长度的延迟边界机制继续作为明确的特殊长度计划存在，不向一般求值暴露占位零。

### 5. 运行时数值和 JSON 值分层

普通整数及 1–64 bit 游标操作采用 long 表示位模式。完整字节宽度优先使用 ByteBuf 整数读写；非标准宽度和跨字节字段使用 long 移位/掩码，显式处理 64 位移位及有符号边界。u64 高位通过无符号位模式及边界转换处理，不使用浮点中转。

保留公开长整数的十进制字符串表示；内部依赖使用规范化精确值，序列化边界才应用 JSON 安全整数规则。受控表达式的既有精确整数语义保留，可在需要时提升至 BigInteger，不要求所有算术都手工实现溢出提升。

字节字段写出后，只有后续条件、表达式或 Trace 需要规范化值时才计算一次。依赖的是实际写出字节所对应的值，保留现有填充、字符串、浮点窄化及扩展的语义。无依赖、无 Trace 的编码不建立完整结果树、不逐字节生成 Integer 列表、不调用扩展 decode。规范化按需缓存到执行帧；不能为了省一次转换而把缓冲区或懒值暴露到调用结束之后。

调试服务保留其显式“编码后解码以展示线上值”的入口行为，但那是独立操作，不属于生产 encode。Trace 需要的字段值最多规范化一次；调试完整解码另计，不为减少这次调试操作而扩张生产 API。

### 6. 表达式定义与用途

保留 DynamicExpression 的 AST 形式并增加 engine/source/bindings 分支。为了保留调用方源代码，新增 record 分量时提供原有构造签名及 builder 的兼容入口；没有新增字段的 JSON 保持原样。schemaVersion 1 接受新增可选形式，旧读者不承诺理解新增形式。

运算符名称明确区分布尔与位运算：AND/OR/NOT 对应 and/or/not 与 &&/||/!，BIT_AND/BIT_OR/BIT_XOR/BIT_NOT 对应 bitAnd/bitOr/bitXor/bitNot 与 &/|/^/~。bitNot 是一元无固定位宽整数取反，等价于 -x - 1；需要字段位宽掩码时显式使用 bitAnd。逻辑运算要求 Boolean，and/or 短路，不采用 Python 的真假值及返回操作数规则。all/any/xor 作为输入别名保留，导出统一使用规范名称。早期位运算 and/or 定义迁移到 bitAnd/bitOr，原有 ALL/ANY Java 常量改为 AND/OR；这是明确的兼容例外，不按操作数类型猜测 and/or 的含义。

引擎表达式示例：

```json
{
  "id": "adjustedLength",
  "type": "derived",
  "expression": {
    "engine": "SpEL",
    "source": "#length + 2",
    "bindings": { "length": "header.payloadLength" }
  }
}
```

用途统一为 derived.expression、when.expression、length.expression。旧 when.ref/op/value 和 when.expression 互斥；length 的五种来源互斥，unit 仍明确。不新增第二种条件属性名，也不让任意表达式位置接受多套非等价字符串简写。

bindings 的键采用字段标识同样的命名规则，保留 self 名称不允许绑定；值采用既有 DSL 引用规则。显式绑定为空 Map 可表示无字段依赖，不能省略绑定后自动注入全部字段。编译器验证绑定目标，不声称能分析引擎源码内所有自由变量或动态索引。

### 7. 复用 XtreamExpressionEngine 的边界

增加一个明确的编译选项入口（拟名 DynamicCompileOptions），携带协议版本、扩展注册表和可选的宿主表达式注册表；现有 compile 重载委托到默认选项。选项不是通用插件容器，不影响已生成计划的生命周期。缺省不构造默认 XtreamExpressionEngineRegistry，因为它会自动注册全部内置引擎。

引擎仅在编译时查找并绑定，执行计划持有对应 XtreamExpression 及创建上下文所需的引擎实例，不在执行时依赖可变注册表。注册表更新不替换现有计划；宿主在编译期间应保持注册配置稳定。通过现有引擎 id 合同适配字符串标识，不为动态模块复制注册表实现。

内部用一个薄的 CompiledValueExpression 合同连接当前执行帧与结果：AST 直接编译为常量、引用和受控运算；引擎实现委托 XtreamExpression。AST 不先序列化或翻译为其他语言。表达式节点数量与深度在编译前受限，常量和操作数大小在可能的大整数分配前校验。

引擎上下文在每次求值时从已声明绑定创建，先选择这个简单且隔离的实现，避免可变表达式环境跨元素泄漏；上下文分配通过基准记录。后续只在有证据且能保证环境完整重置时考虑复用，当前不引入缓存。绑定值提供只读的公开值快照，不暴露执行帧、可变输入对象、ByteBuf 或宿主服务；不得把 AST 路径也变成每次复制 Map 的实现。

表达式和引擎实例必须可并发复用，用三种内置引擎及记录调用次数的测试引擎验证。自定义实例的并发能力是宿主实现责任，文档必须写明；不能仅因为上下文独立就声称所有第三方引擎天然线程安全。

### 8. 统一结果检查，保留语言差异

通过 evaluate(context, null) 获取原始结果，再由动态层按用途检查。条件严格接受 Boolean；长度/计数接受精确整数和既有无损整数表示，拒绝浮点、负数及溢出；派生结果限定为公开值模型可表示的数据，整数仍按公开 JSON 规则输出，不把任意引擎对象流入 Trace 序列化。

受控 AST 保持当前比较及短路语义；三种引擎各自的除法、类型提升、相等语义不做透明改写。文档给出各引擎自己的样例。缺失的显式绑定在调用引擎前失败；旧 when 简写在源字段缺失时为 false，保持既有行为。显式表达式条件不把缺失、null 或异常转换成 false。

编译语法失败使用表达式所属 DSL 位置，执行失败附加当前 bit 偏移、用途、引擎标识并保留 cause。执行器负责统一 Trace 诊断，不在每层重复记录同一个失败。

### 9. 宿主配置与资源边界

默认 core 入口和独立调试应用仅启用受控 AST。调试服务增加宿主可选编译配置入口；HTTP 请求仅提供引擎 id，不提供注册、类加载或上下文服务注入能力。复用现有 JSON 输入和错误响应，不新增引擎管理路由。

通用引擎不是受控 AST 的沙箱替代品；SpEL 当前上下文含反射属性访问，MVEL/Aviator 也各有语言能力。显式 bindings 控制字段依赖，并不限制源码本身的全部能力。只读值和宿主白名单不能被宣传为通用代码隔离；启用这类表达式的宿主负责来源和引擎配置。保留现有引擎实现，不在本次承诺安全超时。

未知 TLV 的 rawHex 在 parseHex 前同时校验字节数、条目前缀、父边界和全局剩余输出。引擎管理的分配均在分配前验证；扩展 encode 内部的任意分配无法由 byte[] 返回式 SPI 强制限制，只能检查返回值并明确宿主责任，不声称覆盖扩展内部内存。

### 10. Trace 与性能验收

Trace 按需创建，不引入通用监听器总线。源位范围使用编译后的引用位置查找；节点路径和集合下标用于诊断，Trace 的公开字节/位合同保持一致。为 Trace 分配的范围表和节点表不在无 Trace 执行中创建。

基准在修改前、完成后使用同一 JDK、硬件和参数运行，记录 ns/op、B/op 和误差。矩阵包含整数 encode/decode、跨字节位字段、较大 bytes/string、嵌套集合、TLV、回填、受控表达式及三种引擎；有无 Trace 分开测量，编译成本单独测量，不能混入执行对比。

预期普通整数、无依赖大 bytes 编码的分配明显下降；显式表达式求值应展示其上下文开销。验收必须能解释增加的分配及超过噪声的退化，不以单次短测的固定倍率做承诺。用扩展调用次数、重复执行的表达式创建次数和独立预期字节测试验证结构性的优化，避免只依赖微基准结论。

## Risks / Trade-offs

- 内部类型和执行帧重构范围较大 → 先打通混合位字段、回填、集合、条件及 Trace 的垂直样例，再迁移剩余节点；旧实现只作临时对照，完成后删除。
- 老实现的成功往返可能掩盖相同错误 → 使用独立预期 HEX、消费量和负例断言，不能只比较新旧结果或 encode/decode 自洽。
- 规范化值按需处理可能改变引用语义 → 以实际写出值作为后续语义依据，覆盖填充、浮点窄化、扩展以及多个依赖的调用次数。
- 显式引擎表达式扩大执行能力 → 默认不启用；标明宿主责任，语法及数值语义按引擎记录，不宣称自动沙箱。
- 公共 record 增加分量 → 保留构造重载，验证旧 Java 示例及 JSON 往返；不承诺反射读取 record 分量数量的调用方完全不受影响。
- 前序规格尚未归档 → 保留当前文件，归档时先同步前序主规格再应用本次 delta，检查只有一个 Purpose 和 Requirements 区块。

## Migration Plan

1. 记录既有测试和基准，补齐已复现问题及上述组合语义的预期断言。
2. 编译布局、值引用、作用域和回填动作，使用内部测试打通垂直样例；临时新旧路径仅用于迁移，不增加公开开关。
3. 迁移全部节点和方向，接入 Trace、资源和异常规则，替换公开入口的内部委托，删除旧路径 Map、模板执行流程和无用结果重建。
4. 扩展表达式定义，接入宿主引擎、结果检查和服务配置；完成并发及调用次数测试。
5. 验证旧实体、动态 DSL、808 多版本示例、独立工具、文档及完整基准，逐条完成 tasks。
6. 发布前可通过恢复旧内部委托回滚尚未完成的迁移；完成后的新引擎表达式是新增能力，回滚时须同时停用含新增语法的定义，不能把它交给旧解析器。归档单独执行，遵守前序依赖顺序。
