# Proposal

## Why

同一站点的多个浏览器标签页目前把整个工作区写入 IndexedDB 的同一个 `current` 键，编辑、切到后台等操作会相互覆盖草稿备份。服务器虽已拒绝旧版本保存，但用户遇到冲突后只能看到错误，无法直接选择采用哪一方的内容。

## What Changes

- 按浏览器标签页隔离工作区草稿，保留各自的报文标签、未保存原文、活动报文、固定及排序状态和最近运行结果；编辑器内部的报文标签仍属于同一个工作区。
- 明确刷新、复制浏览器标签页、重新打开页面和旧草稿迁移的恢复规则；初始快照可以复制，后续备份必须独立。
- 保存同一服务器报文发生版本冲突时，提供“使用服务器版本”“用本地版本覆盖服务器”和“取消”，明确说明各操作丢弃哪一方的内容。
- 本地覆盖服务器仍基于用户确认的服务器版本提交；服务器再次变化时重新提示，不自动重试覆盖，不支持自动合并。
- 取消、获取失败、保存失败及服务器报文被删除时保留本地编辑；成功后的保存基线和异步结果归属保持一致。

## Capabilities

### New Capabilities

- `studio-browser-sessions`: 浏览器标签页之间的草稿隔离、复制、恢复及旧存储兼容。
- `studio-save-conflicts`: 保存冲突的双向版本选择、取消、重复冲突和失败保留行为。

### Modified Capabilities

无。主规格目前尚无 Studio 能力；已完成但未归档的 `upgrade-codec-studio-workspace` 定义了 `studio-editor` 和 `studio-workspace`。本变更新增上述两项独立能力，建立在已有编辑与版本检查之上，不改写该变更或重复声明其已有要求。

## Impact

- 前端：`draft-store.ts`、`api.ts`、`app.tsx`、`workspace.ts` 及冲突弹窗组件，更新相关测试和 UI README。
- 存储：从全站单份草稿演进为独立工作区记录，保留现有 IndexedDB 和旧 localStorage 草稿的迁移来源；主题及布局偏好继续作为站点级配置。
- 后端：复用已有 GET、PUT、`expectedRevision` 和 HTTP 409 合同；补充必要合同验证，不增加绕过版本检查的强制写入接口。
- 依赖与边界：不引入协同编辑、自动合并、历史版本管理或新第三方运行时依赖；不改变编解码、服务器持久化介质及公共 Java API。
