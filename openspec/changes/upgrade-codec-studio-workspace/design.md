# Design

## Context

现有 React App 按模式保存 Draft，result/pending 是全局状态；JSON 编辑原文未进入草稿。Java HttpServer 仅适配 core 调试服务。工作区实现放入顶层 studio-app 的独立 workspace 包，不让 core 依赖文件系统、数据库或 UI。

## Goals / Non-Goals

Goals：保持既有编解码与 HeroUI 交互；让切换、异步请求、恢复及保存以文档身份绑定；两种存储通过相同合同测试。
Non-Goals：账号与多人协同、完整执行历史、Dashboard 页面、运行时更换介质、任意远程 SQL 配置。

## Decisions

1. 顶层 app/ui 同时迁移及改名，Java 应用包改为 codec.studio.app，保留 core.debugger。统一 Gradle Java 白名单、构建开关及相对路径。复用 application 分发任务。
2. 文档保存 Draft、schemaText、schemaTab 与最近运行快照（执行方向、输入签名、时间、结果）。原文允许未完成，执行才解析；dirty 比较持久内容，不以 UI 切换作为修改。运行响应按捕获的 tabId 写回，标签切换保持 CodeMirror/Trace 组件的实例状态，仅挂载打开的文档。
3. 前端工作区协调器维护标签和服务目录；可复用编辑组件承担原 App 的字段编辑与执行。运行面板在各文档内保留实例，底部停靠、内部滚动，上边界用可键盘操作的 separator 调整高度。标签主题和目录展开等是客户端状态。
4. IndexedDB 异步保存工作区草稿；首次恢复读取旧 localStorage，迁移三种模式草稿。只在恢复副本写入成功后视为可恢复，错误显示提示。Ctrl/Cmd+S 正式保存到后端；失败保持 dirty；保存过程中再次修改不会被响应覆盖。
5. WorkspaceEntry 使用 UUID、parentId、kind、name、revision、更新时间，文档 payload 是版本化 JSON 原文对象。WorkspaceService 校验目录图、同目录唯一名、移动及递归删除，提供 GET /api/v1/workspace，POST /entries，PUT/DELETE /entries/{id}，GET /export，POST /import。每条更新传 expectedRevision；介质提交另有整体快照 revision，避免并发产生悬空目录。
6. WorkspaceStore 只提供读取快照及带版本的原子提交，service 负责领域规则，接口与 HTTP 无关。FileWorkspaceStore 为每条记录保存独立版本 JSON，原子替换 manifest 发布完整修改；启动持有数据目录锁，禁止多个进程同时操作。SQLite 用 JDBC 和事务保存元数据及 JSON，整体版本比较与更新在同一事务。限制数据规模并使用同一合同测试重启、冲突和导入原子性。
7. 配置以系统属性或环境变量选择 file/sqlite 与数据路径。默认目录 ~/.xtream-codec/studio；自定义 WorkspaceStoreProvider 通过 ServiceLoader 加载，嵌入应用可直接传入 WorkspaceService。内置 sqlite-jdbc 随应用提供，不传递到 core。
8. 文档文件格式 studio-document v1，工作区 studio-workspace v1；导入新增并重映射 ID，校验整个备份后一次提交，顶层使用独立导入目录避免与原有名称冲突。导出保留结果快照，草稿格式另有版本；不保存临时 pending 状态。
9. 编辑区采用紧凑分栏面板，共用可键盘操作的分隔线；栏内划分按比例、侧栏宽度和运行面板高度按像素保存。布局偏好单独存入 localStorage，不进入报文内容或草稿保存基线；根据容器实际尺寸限制拖动范围，窄屏禁用分栏并恢复文档滚动。
10. 拖动预览通过 requestAnimationFrame 合并指针位移，直接更新对应容器的 CSS 变量或高度，不更新全局 React 布局状态；松手提交最终坐标一次，键盘调整仍直接提交。取消时恢复起始尺寸，卸载时取消待执行帧及拖动覆盖层，保留 React 已应用的新布局样式。
11. 活动文档信息、版本配置、连接状态与命令由工作区统一绘制工具栏；版本修改直接按活动标签身份写回。工具栏按自身容器宽度切换单行或两行分组，兼容侧栏调整，不在隐藏的文档编辑组件中重复渲染配置。
12. 视觉边界区分主要分区、次级分隔与层级引导；字段条目以留白及交互背景组织，类型颜色集中到标签，嵌套仅保留中性引导线。输入和错误、焦点及选中状态保持明确，不降低现有信息密度或改变面板调整能力。
13. 文件树使用浏览器拖放，以独立数据类型和本地拖动身份限制为树内移动；仅文件夹与拖动时显示的根目录落点接受有效移动。前端过滤自身、后代和原父目录，后端继续负责重名、版本与目录合同；复用菜单的元数据更新流程，读取正式文档后修改目录，不提交标签草稿，标签旧版本不自动升级。
14. 字段排序按同级目标条目的上下半区确定前后插入位置，移除源字段后修正目标索引；落点指示线与文字使用绝对定位，避免拖动中改变布局。拖动状态只在当前结构编辑器内维护，无效或无变化的落点不显示提示，取消与结束统一清理。
15. HEX 下方的字节预览始终展开，使用静态标题保留字段路径与片段范围。Bit、编码和数值分别使用中性细边框、8px 圆角和 10px 内边距的小卡片，宽容器并列、窄容器自动换行；bit 单元固定为紧凑尺寸，卡片内容超宽时内部滚动或换行。三类预览共用当前最多八字节的片段并显示半开字节范围；位字段仍高亮对应物理位，编码与整数按完整原始字节展示，明确提示非对齐边界。整数使用 BigInt 保留八字节精度，ASCII 控制字符用点显示，无效 BCD 不作为数字展示。

16. 动态字段 Trace 保留包含长度前缀的完整范围，已消费的前缀作为 LENGTH_FIELD 同级节点插入对应字段之前；字段通过 contentBitStart/contentBitEnd 属性提供内容范围，前缀通过 fieldPath 属性关联对应字段，不改变 Node 的公共构造器。前缀命名为 prependLengthField(字段名)，显示为“字段名 前置长度”，区分同一容器中的多个前缀及数组元素。编码回填完成后从最终缓冲区读取前缀值；失败时保留已读取前缀，未完成的容器回填不显示成功值。Studio 的 HEX 高亮、位图与编码、整数预览共用内容范围，选择前缀节点仅高亮前缀，空内容不定位或高亮前缀及相邻字节；旧结果没有属性时沿用原范围。
17. Studio 明暗主题使用中性的黑灰/白灰层级，蓝、青绿、紫、金等主题色板用于字段类型，红色用于错误状态；主操作继续使用用户选定的主题色。Trace 的圆点、类型标签与详情按显示类型名称稳定着色，同类型长度节点与普通字段使用相同颜色，错误状态覆盖为红色；编辑器文字与背景使用同一组主题变量。自定义 CodeMirror 主题优先于默认主题，行号栏与编辑器使用同一中性底色，浅色行号栏的 1px 竖向分隔线使用主分区边界色，暗色保留较淡的引导线，当前行号以中性色强调。
18. Trace 树使用节点、类型、位范围和值四列，表头与所有节点共用列宽，缩进仅作用于名称列。节点用字段路径与内联说明单行展示，不重复显示名称和路径；动态字段使用 displayName，实体字段使用 fieldDesc，说明与名称相同时省略，行间用淡分隔线区分。收紧行高和上下留白，类型标记采用紧凑圆角标签。长路径、说明和值截断并提供完整提示，表头随树纵向滚动保持可见。表头和节点共用最小宽度为 760px 的内容容器，窄面板保持四列单行并在树内横向滚动，不引入页面横向溢出，折叠按钮保持独立键盘操作。
19. 运行结果的状态、消费统计、校验和摘要与操作合并为紧凑工具栏，窄容器自动换行；校验和摘要保留字段、实际值、期望值和匹配状态，算法与完整说明放在悬停提示，不为成功校验保留独立通知区域。工具栏最高占用结果区域的 35% 且不超过 120px，内容较多或高度不足时可滚动，避免多项校验挤压 Trace。运行面板及结果标签采用受限高度的弹性布局，HEX 与字段跟踪各自固定标题、滚动内容并占据剩余高度，取消 Trace 树固定高度上限；节点详情与树共用滚动区域，字节预览随 HEX 栏滚动。窄屏上下排列时平分可用高度并各自滚动，高度不足时恢复左右排列以保留可滚动内容。诊断区限制高度并可滚动，字段值和完整响应编辑器填满标签页，避免长结果挤出操作区。
20. 主分区使用独立的中性边界变量，明暗主题分别提供可辨认的细线；结构、编码、解码与运行面板采用 IDEA 风格的 8px 圆角、1px 细边框及 6px 窄间距，编辑区分隔线保留原有拖动轨道，不叠加贯穿面板的共享线。HEX/Trace 保留低对比细边框和 8px 圆角，标题以底色和较淡分隔线组织；运行面板标题左侧按红、黄、绿排列关闭、折叠、最大化控制，12px 圆点保留较大的点击区域，悬停或键盘聚焦时显示操作图标。分隔线悬停、焦点和拖动采用主题色，窄屏上下排列仍保留圆角与窄间距；字段内部的分隔与层级引导保持淡色，不改变语义色。
21. 动态编译布局保留字段声明类型，启用跟踪时通过 `attributes.dataType` 返回，长度前缀使用对应的 `uN`；类型跟随实际执行分支及数组元素返回，不从编辑中的 Schema 推测旧结果。Trace 类型列优先显示动态声明类型或实体的简短 Java 类型，完整 Java 名称及节点类别保留悬停提示；颜色使用同一显示类型名称计算稳定 hash，无类型的旧结果回退到原节点类别。
22. TLV/map/pair 使用输入或线上条目序号作为 MAP_ENTRY 路径下标，`entryIndex` 和 `key` 属性区分序号与键值，内联说明显示 Tag/Key 值；不按键排序，也不把重复键合并。每个条目覆盖完整头部和内容，下挂 Tag/Key、Length（pair 除外）和 Value，Length 保留 LENGTH_FIELD 类别及实际整数类型，整数头部使用 uN，未知 Value 使用 hex。已知 Value 继续走原分支执行入口以保留作用域、声明类型和嵌套字段；编码 Length 在回填后更新成功值，失败时保留已完成子节点和未完成的回填状态。Studio 直接使用后端树和范围展示、折叠及定位，不从编辑中的 Schema 拼造节点。
23. JSON 与解码 HEX 共用 CodeEditor 的 CodeMirror 主题、行号、当前行和选区。JSON 继续启用语言解析、自动折行及既有 DSL 补全；HEX 使用普通文本和琥珀色，关闭自动折行、JSON 补全及括号配对，长行在编辑器内横向滚动，显式换行原样保留。HEX 编辑器沿用编码区的受限高度布局，填满解码面板，标题和字节统计、解码按钮固定；窄屏保留 180px 输入高度。只在执行时使用既有 HEX 规范化，编辑和草稿恢复不改写输入原文。

24. 结果 HEX 使用固定 32px 正方形字节格与 4px 间距，列坐标与字节共用固定网格，偏移列保留四位十六进制标签。表头下方和偏移列右侧使用中性细线形成坐标轴，坐标标签采用淡边框；表格不随面板宽度拉伸，窄面板在 HEX 内横向滚动，保留字段高亮、字节选择、分页及独立滚动。

25. 数值卡片顶部优先展示选中节点的 Trace 实际值、实际类型及完整字段位宽，字段值不随八字节预览分段截断。整数使用 BigInt 从 Trace 值生成 HEX/BIN，负数按字段位宽展示补码，不从边界字节重新解码；非整数仅显示已有字段摘要，不将字符串、容器等强制解释为数字。旧快照缺少值时使用摘要，失败或尚未完成节点明确标识状态且不生成成功整数预览。原始字节数值保留大小端和有符号解释，编码卡片标明原始字节，两者显示当前片段字节范围；非字节对齐提示明确仅指原始字节解释。

26. 可视化字段摘要将长度前缀自身的占用位数与前缀值表示的计数单位分开显示，整字节位宽补充字节换算，非整字节位宽仅显示实际位数。配置弹窗明确标注输入的单位为 bit，并按 byte/bit/item 和当前位宽提供可表示的前缀值示例；长度配置 JSON 与编解码语义保持不变。

27. FieldTrace 使用显示类型名称的 FNV-1a 稳定 hash 选择固定蓝、紫、绿、金、青色板；只依赖类型名称，不依赖路径、节点职责、出现顺序或当前结果中的类型集合。类型标签、圆点与选中节点详情共用颜色计算，ERROR/FAILED 覆盖为错误红色；主操作主题色仅影响选中行背景。固定色板使用现有明暗主题变量，允许不同类型落入同一颜色，保证同类型着色稳定并避免普通类型使用错误红色。

28. HEX 点击继续复用 nodeIdsByByteOffset 的节点选择和祖先展开逻辑，每次显式选择递增定位请求。在 DOM 更新后的 layout effect 中比较选中行与 trace-tree 可视区的纵向边界，扣除固定表头高度，仅对超出边界的行使用原生 scrollTo 平滑调整树的纵向位置；已可见时保持位置。每次定位先停止尚未完成的滚动，再以当前选择为目标；系统偏好减少动态效果时立即定位。重复点击相同字节仍触发定位，树的横向位置、HEX 与页面滚动不变；从 Trace 或关联字段按钮选择节点共用此行为，手动滚动、折叠、主题或文档切换不额外触发定位。

## Risks / Trade-offs

- 大型 Trace 增加草稿与存储体积 → 只保存最近一次、请求与工作区大小限制，IndexedDB 使用异步写入。
- 并发保存覆盖 → entry revision 与 store revision 两层比较，冲突要求重新打开或另存文档。
- 浏览器恢复副本和后端不同 → 后端是正式文档，草稿只恢复未保存状态，不自动覆盖服务器。
- 文件多记录原子性 → 先写独立记录，再发布 manifest；失败保持原 manifest，遗留临时记录在启动清理。
- SQLite 可备份性 → 工作区导出为跨介质备份入口，运行中不建议直接复制数据库文件。

## Migration Plan

先迁移模块并跑已有测试；实现工作区后端与合同测试，再接入编辑器；保留旧 localStorage 直至迁移恢复成功。升级命令写入 README，历史归档 OpenSpec 不重写。回滚可恢复旧模块代码，正式工作区保留在独立数据目录。
