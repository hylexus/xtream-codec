# 覆盖设计

## Context

见 [proposal.md](proposal.md)。现有 34 个模块测试已覆盖同一 TCP 连接内的顺序、UDP 同步异常隔离、并发会话创建与关闭、交换上下文复用及构建器配置。下一步从这些用例之外的公开执行入口补测。

## Goals / Non-Goals

- 每轮保存模块测试、行和分支覆盖率以及失败复现和修复后验证的证据。
- 当测试发现违背现有约定的缺陷时，先运行用例证明失败，再最小化修复。
- 覆盖工作仅针对非废弃入口，使用现有 JUnit、Reactor 和 Netty 测试能力。

## Decisions

1. 第一轮走真实请求分发入口及响应发布器，验证组件优先级、短路、同步与异步异常、缓冲区交接和主动下发。
2. 第二轮验证事件订阅、取消与关闭，并补会话空闲和传输生命周期的公共行为。并发测试使用显式同步或虚拟时钟，等待设置上限。
3. 第三轮用覆盖率差异定位仍缺失的活跃分支，补参数解析、请求构建、调度及入站错误处理的边界。验证行为和资源状态，避免仅为覆盖率调用访问器。
4. 临时 JaCoCo 脚本只配置本模块。各轮保留 XML，统计模块全部字节码，废弃成员仍计入总数。记录使用同一口径。
5. 第四轮用真实引用计数覆盖发送侧接收前、接收后和失败后的状态。已交给 Reactor Netty 的引用由发送侧处理。
6. 第五轮用 latch 固定事件投递与关闭的时序，验证订阅终止和线程退出。定时任务用有界等待观察退避、取消和重启。
7. 第六轮通过通用 TCP 构建器、测试包扫描及回环临时端口验证真实请求解码、匹配、处理和应答。
8. 回环测试复现默认会话管理器在 TCP 对端断开后仍保留会话。登记后绑定到通道关闭事件，继续使用按对象关闭和已有的回调顺序。
9. 第七轮使用真实回环端口验证 TCP 停服取消在途处理和释放缓冲区，UDP 用两个源端口对照会话标识、应答地址和到期重建。Disruptor 用容量为二的队列和 latch 验证等待入队的生产者、排空和关闭顺序。
10. 第八轮从通用 TCP/UDP 构建器验证默认管理器随绑定启停，并对照显式提供的管理器。TCP 回环用例通过控制 flush 和发布顺序固定断连时的缓冲区状态，并保留一个独立引用以检测重复释放。
11. 第九轮让两个 UDP 客户端的请求同时挂起，使用通道关闭验证取消、引用释放和重启后的应答。Disruptor 用容量为二的队列和同步订阅回调固定关闭时序，验证已接纳事件排空及消费线程退出。
12. 第十轮用回环客户端确认后续分组挂起时第一组已送达，并验证断连清理。JT/T 808 starter 通过真实 Spring 自动配置启动指令 TCP 服务，核验容器关闭时连接、监听端口和内置资源工厂创建的 event loop 均释放。
13. JT/T 808 内置指令和附件服务的 TCP/UDP Bean 使用现有 `stop()` 作为销毁方法。Spring 按 Bean 依赖顺序先停止服务，再释放其内置资源工厂创建的 event loop。
14. 第十一轮用真实 TCP 请求建立会话并等待入站引用释放，再按会话 ID 走通用主动下发，检查客户端实际收到的字节和出站缓冲区引用。JT/T 1078 starter 在同一个 Spring 容器启动 TCP 和 UDP 监听，关闭容器后检查 TCP 断连、两个监听地址可重新绑定和各自的 event loop 终止。内置 TCP/UDP 服务和资源工厂沿用 JT/T 808 的销毁顺序。
15. 第十二轮预占回环 UDP 端口，通过 JT/T 1078 starter 自动配置先启动 TCP，再尝试启动 UDP。检查 Spring 启动异常保留实际端口的绑定错误、TCP 监听关闭且原地址可立即重新绑定、TCP 与 UDP 已创建的 NIO event loop 均终止。
16. 第十三轮在 JT/T 808 starter 实际自动配置中启动内置处理器调度器的线程，验证关闭容器后调度器释放和线程退出，同时验证应用注册的共享调度器仍可执行任务。使用单线程调度器阻塞工作线程，确认真实 TCP 请求已排队后断开客户端，核对处理方法的调用次数和入站缓冲区引用。
17. JT/T 808 的调度器定制器仅跟踪自己创建并成功注册的调度器，Spring 销毁定制器 Bean 时释放这些资源。注册失败的调度器立即释放。
18. 第十四轮使用 JT/T 1078 starter 的实际自动配置，让编解码和订阅调度器分别执行一个任务，关闭容器后检查调度器释放和工作线程终止。
19. JT/T 1078 的调度器定制器沿用 JT/T 808 的资源归属规则，在 Spring 销毁定制器 Bean 时释放自己创建并成功注册的调度器，注册失败时立即释放。
20. 第十五轮在旧会话登记期间创建 JT/T 808 指令下发 `Mono`，在订阅前用同一终端的新会话取代旧会话。订阅时按终端 ID 查找当前会话，核对新会话收到指令且下发返回终端应答。
21. 通用 TCP 回环测试占满处理器调度器的唯一工作线程和一格队列，核对异常处理器收到调度拒绝、处理方法未执行、入站缓冲区引用归零。待队列腾出容量后，在同一连接发送下一帧并核对应答。
22. 第十六轮通过 Caffeine 的缓存策略触发未完成分包到期和容量淘汰，检查缓存留存的正文引用归零，再用同一终端的完整分包验证正文与首包流水号。
23. 通过 JT/T 808 starter 自动配置和真实回环连接触发 TCP 读空闲。已登记会话的客户端发送合法心跳帧，无会话的客户端只建立连接。两个客户端均读到 EOF，已登记会话只发出一次 `EXPIRED` 关闭通知。
24. 第十七轮通过 JT/T 808 starter 自动配置在同一条真实 TCP 连接下发两条位置查询。从线上指令取流水号，用不同报文流水号倒序发送位置查询应答，由注解处理器解码并关联两条等待链。
25. 通过 Spring 自动配置获取默认分包合并器，保留一组未收齐的分包和一条已经完成合并的请求。关闭容器时，检查缓存持有的引用立即释放，合并结果持有的引用在请求释放前仍可读取。
26. Netty 资源工厂的 `@Bean` 方法继续返回 TCP 或 UDP 接口，内置 Bean 显式声明 `destroyMethod = "dispose"`。用 JT/T 808 指令 TCP 服务验证同名接口实现可以替换内置工厂，其共享事件循环在应用上下文关闭后仍可执行任务。
27. 在 TCP、UDP 工厂共用的 `XtreamNettyResourceFactory` 声明默认空操作 `dispose()`，让 Spring 可以从 Bean 的声明类型解析销毁回调。`BaseXtreamNettyResourceFactory` 覆写此方法并释放它创建的事件循环。只实现原有接口方法的工厂可沿用原实现。
28. JT/T 808 的内置发布器 Bean 在销毁时走 `shutdownGracefully()`。发布器发起原有关闭流程，最多等待五秒让已登记的订阅结束，随后由 Spring 释放内置订阅调度器。普通 `shutdown()` 保留原有等待语义，接口默认实现委托给 `shutdown()`。
29. 通用 UDP 构建器总是调用 `createRequestHandler()`。构建时装配处理链，并读取显式配置的会话管理器。使用默认管理器时，每个绑定仍在处理订阅中创建并关闭自己的管理器。
30. 将原始 ByteBuf 交给出站前保留可清理的引用。出站有需求后，将原始值交给主动下发的 `doEncode()` 或应答的 `encode()`。出站提前拒绝或取消时，释放尚未交接的引用。

## Risks / Trade-offs

- Reactor Netty 发送会接管缓冲区引用。出站用例在接收和跳过订阅两种路径上检查最终引用计数。
- 测试用临时端口、受控调度器和关闭钩子。异常路径也释放测试创建的资源。
- 测试揭示的修复可能影响下游。最终运行 JT/T 808 starter 和独立压测应用的测试。
