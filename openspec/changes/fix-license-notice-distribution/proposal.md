# Proposal

## Why

仓库将依赖报告重命名为 NOTICE，但没有维护复制源码的归属声明，源码和 Javadoc 归档也没有统一携带许可证。统一文件头还可能覆盖上游声明，需要修正已确认的问题，并明确尚未核实的分发风险。

## What Changes

- 增加项目 NOTICE 与来源审查记录，区分源码归属、依赖许可和待核实来源。
- 为普通、源码、Javadoc JAR 统一附带 LICENSE、NOTICE；依赖报告保留显式生成入口，类库和应用打包均不强制生成或携带报告。
- 为已能从本地上游源码核实的 Apache 派生文件恢复版权声明，避免格式化任务覆盖这些声明。
- 调整 Studio Shadow 归档，保留不同依赖的许可与归属文件。
- 补齐 ADPCM 的 MPL 声明及对应源码、jump3r 的 LGPL 分发与重建/替换材料；未确认的其他来源保留发布待办。
- 为八个前端构建按实际打包模块生成许可全文，并随静态资源分发；规范 docs 的 SPDX 许可字段。
- 用公开 API 替换明确复制自 JDK 的无符号转换实现，验证边界；保持现有功能与依赖。
- 继续核实 Spring Boot Admin、SmallChi JT808/JT1078、EyerH264Decoder 和 maz-g711 的固定源码快照，恢复适用声明并将 MIT 全文纳入分发；删除不必要的逐字网页表格注释，保留协议数据与行为。
- 记录五个 jt-framework 工具类复用自 hylexus 在该项目中编写的代码，移除对应的第三方贡献授权待办；继续核实 matrixy、ldming、sky 和 jump3r 的剩余声明，补充分发材料和具体证据，保留无法确认的范围。
- 重新绘制项目标志，提供可编辑 SVG、PNG 和各尺寸站点图标，同步实际前端引用及来源记录，替换来源不明的旧标志。
- 替换来源未确认的首页背景和拖拽图标，修复依赖许可检查的实际扫描和渲染器类型问题，统一检查入口；未匹配白名单的依赖仍保留待审状态，音频来源的具体证据缺口单独记录。
- 将 NOTICE 和 THIRD-PARTY-SOURCE-NOTICES.txt 中项目自写的重要说明改为中文在前、英文紧随的逐句对照，逐文件字段使用中英标签，保留上游版权及转载声明原文，核对代表性分发中的 UTF-8 内容。
- 按实际分发范围管理独立 JVM 依赖：普通库仅保留项目及复制源码材料；应用保留上游许可和声明，EPL 提供实际版本的完整源码下载地址。删除逐文件源码索引、审查哈希和固定二进制锁定。
- Boot 保留原始嵌套依赖；Shadow 合并适用许可及声明。必要的补充原文集中维护在一份 `licenses/jvm/open_source_licenses.txt`，各应用共用，各节仅适用于实际包含的组件；打包在汇总中追加实际 EPL 版本的源码下载地址，普通库不附带该汇总。
- Bouncy Castle、Protobuf、OnGres 和 RoaringBitmap 补充材料按上游发行材料维护，保留适用版权和许可，不要求复核依赖的每个源文件。
- 元数据政策改按许可类别及别名匹配，不再使用普通依赖逐版本人工白名单；GPL/LGPL 特殊情况另行处理，jump3r 已知疑问继续保留。
- 移除未使用的 Vite public 图标，提取文档图片中的可编辑数据并生成本地预览清单，记录线索而不推定作者或授权。
- 在共享前端生成器中补齐 THIRD-PARTY-FRONTEND-NOTICES.txt 的关键说明、字段标签和项目补充说明的中英对照，保留上游原文并核对八个前端及代表性后端归档。
- 将 docs 的三个 Font Awesome 6.7.1 字体替换为官方固定 npm 包的原始字节，保留同目录原始许可和双语来源、归档成员及分发说明；验证站点副本及许可汇总，不维护额外审查哈希清单。
- 将少量前端补充原文合并到 `licenses/frontend/open_source_licenses.txt`，保留适用包名、来源和版权，删除精确版本映射、重复正文及额外哈希记录；保留构建自动汇总，按包名和 MIT 声明采用补充，未知缺失许可仍提示处理。
- 提供本地与 GitHub Actions 共用的八前端验证脚本，默认按锁文件安装、生产构建并核对许可材料，专门复验 docs 字体和双语材料，提供明确的本地快速检查选项。
- 整理分发声明与仓库来源记录：仅按已核实对应关系表述复制或改编，技术参考链接单独记录；压缩重复审查过程，保留原始归属、证据、适用范围和具体待办，并复验产物传播。
- JVM 维护说明和随应用生成的分发说明采用中英对照；自动核对实际归档所需原文、EPL 源码地址及 ADPCM/jump3r 特殊材料。
- 前端去掉无关后端材料，完全相同的 npm 许可正文仅输出一次，各包、版本和文件对应关系保留。日常 CI 检查材料，独立 JVM 元数据政策按需手动执行。
- 在文档声明页集中维护中英项目状态、免责与第三方商业责任说明，README、文档首页、导航及随包 NOTICE 提供摘要或入口，保留适用许可证授予的商用权利及上游原文。
- 在醒目摘要、完整说明及随包 NOTICE 中进一步强调：遵守适用许可证即可自由使用、修改、再分发及商用，无需另行取得本项目作者的商业授权；保留适用的版权、许可、归属、修改说明及源码提供等条件，第三方材料仍适用各自许可证。
- 在完整声明页以 Spring Framework 的 Apache-2.0 代码作中英类比，解释许可证使用权、独立商业支持、官方背书和使用者自身代码及商业承诺的责任；示例只帮助理解，不改变正式许可及免责说明。
- 说明可以如实注明使用 xtream-codec 并附项目链接，宣传应准确说明与项目的关系，并按适用许可证保留分发材料。
- 将复制源码的七份许可和声明合并为一份汇总，将 jump3r 使用说明与四份上游原文合并；重建工具移入构建脚本目录但继续随应用分发。删除两份审查 JSON，必要的固定来源、证据限制和未解决事项保留在现有文档，不维护逐文件哈希清单。
- 合并许可维护、依赖检查、音频来源及分发检查说明到一份 README；归档和八前端验证共用单一 Python 入口及测试文件，减少动态加载和重复配置。默认许可头保留独立的 `license-header`，ADPCM 和 sky 专用头集中于 `headers.txt`；jump3r 重建与替换合并为一个工具。图片待核实范围并入现有静态资源说明，统一工具按需生成路径、引用、哈希及可编辑数据预览，不再维护重复手工清单。保留上游许可原文及现有前端生成器。
- jump3r 按未修改依赖的分发义务维护，删除文件头分类统计及固定版本哈希门禁；核对实际坐标、对应版本源码及分发文件的自动校验值，保留 LGPL、上游原文和重建/替换支持。FFT 仅保留针对具体历史声明的简短待办，升级不要求重新审计全库源码。

## Capabilities

### New Capabilities

- `license-distribution`: Java 分发归档保留项目许可、源码来源声明和第三方许可材料。

### Modified Capabilities

无。

## Impact

影响根构建、前端构建配置、Studio 打包配置、派生文件的版权头和许可文档。根 Apache-2.0 许可证及现有 Dashboard MIT 文本保留；不替换音频功能，不宣称完成所有来源的授权核实。
