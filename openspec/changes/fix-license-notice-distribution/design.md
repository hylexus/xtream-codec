# Design

## Context

根构建为所有 Java 子模块配置许可证报告和 JAR 打包，Studio 另有 Shadow 聚合任务。上游源码缓存可核实 Spring 6.1.8、Spring Boot 3.3.0、Reactor 3.6.6 的文件头，但不能证明每个文件最初复制的精确版本。部分音视频代码的历史来源和授权范围仍待核实。

## Goals / Non-Goals

**Goals:** 复用现有 Gradle 任务修复交付材料，并为后续审查保留证据与限制。

**Non-Goals:** 不改动功能或依赖，不将添加 NOTICE 视为补发授权，不将所有项目文件改为同一许可证。

## Decisions

- `build-script/license/README.md` 集中说明日常维护、源码来源与证据限制、发布待办、本地及 CI 检查。图片待核实范围放入现有 `assets/STATIC-ASSETS.md`，路径、引用页和哈希由统一入口的 `--preview-assets` 按需生成，不再同步手工表。归档验证和八前端调度共用 `check-materials.py`，默认构建并核对八前端，显式 `--jar`/`--frontend` 只核对指定产物；前端快速选项及图片预览模式不能与指定产物模式混用。Python 测试共用明确的 `test_check_materials.py`，CI 继续使用同一入口；不引入通用命令框架，不删除现有有效检查或新增依赖。
- 默认头模板保留独立的 `license-header`，ADPCM 和 sky 专用头集中于 `headers.txt` 的两个分节，与源码许可汇总复用分节读取函数；模板原文与现有 Java 头保持一致。jump3r 两个工具合并为 `jump3r.py` 的 `rebuild`/`replace` 子命令，随应用以同名脚本分发，保留源码路径校验、新输出文件、唯一嵌套库、签名及 ZIP 存储检查。更新项目自写使用说明，全部上游许可正文保持原样。

- 保留根 Apache LICENSE 原文，新增 NOTICE 描述已确认派生来源；复制许可证不进行模板展开。
- 通过共享 CopySpec 为普通、源码及 Javadoc JAR 附带项目和复制源码材料；普通库不生成、附带独立依赖报告或完整依赖源码，避免打包类库也解析整棵依赖树。
- 恢复从本地上游源归档验证的版权行；为这些文件配置对应头模板，避免跳过所有已有文件头而削弱全项目检查。
- Shadow 对同名许可和归属文件使用追加转换，保留各文件内容；类库和应用打包均不强制生成或携带依赖报告，报告和元数据政策检查保留显式入口。
- 详细来源清单与未解决项放入 build-script/license 审查文档；根 NOTICE 保留归属信息及项目自写的状态、免责与无背书说明，不承载许可合规结论或改变上游条款。
- 分发声明保留已核实的来源、适配范围和必要的许可边界；参考链接未建立源码对应关系时不表述为复制事实。仓库审查记录同样按公开文档维护，集中保留固定版本、URL、哈希、比较结果及具体待办；重复验证过程按范围汇总，保留比较快照不等于历史首次引入等证据限制。原始版权、转载声明与许可正文不改写，未解决的 jump3r FFT、图片及依赖政策事项继续明确记录。
- AAC 类注释仅将识别并跳过 7 字节 ADTS 头的处理思路归于 sky，链接用于介绍相关 JT1078 项目。该项按技术方案参考维护，不因参考思路或项目链接本身推定源码复制或设立覆盖整个类的授权待办；历史查询记录保留，消息解码器的 Mulan 授权范围不扩展到该类。后续若识别出具体源码复用，按对应源码和许可补充材料。
- 上游比较类作者集中记录在 THIRD-PARTY-SOURCE-NOTICES.txt 并随归档分发，说明其不是当前项目贡献者名单，也不能据此推定具体方法的个人作者。保留原有作者标签；上游版权行不变，追加的项目版权行明确仅适用于 xtream-codec 修改部分。
- ADPCM 派生文件保留 MPL-2.0 及项目修改声明；其二进制 JAR 同时携带该文件的实际 Java 源码、许可全文与来源说明。matrixy 的适用声明单独保留；Microchip 历史引用与当前实现的比较记录见音频来源文档，不由 MPL 声明推定其他来源的授权。
- jump3r 材料仅随实际捆绑该依赖的 Boot/Shadow 应用提供；按 runtimeClasspath 获取匹配 sources JAR，附带 LGPL、原声明和重建/替换工具。使用说明与四份 LAME 上游原文合并为 `licenses/jump3r/NOTICE.txt`，工具维护于 `build-script/license/jump3r.py`，归档中仍与源码同目录。删除文件头分类统计及固定版本哈希门禁；`ARTIFACTS.txt` 的坐标和校验值由构建生成，检查对应版本源码及实际嵌套库的完整性，不表示逐版本人工批准。FFT 的具体历史声明仅在发布待办保留一条记录，升级依据上游许可和发行材料维护，无需重新审计全库源码。
- 前端共享 Vite 插件从实际输出的 JavaScript 模块及加载的样式定位安装包；空入口和完全移除的转导出模块不纳入。收集完整 LICENSE/NOTICE/COPYING 文本，不按 package.json 的许可短名生成替代文本。少量缺失原文集中到共用的 `licenses/frontend/open_source_licenses.txt`，按其中“适用包 / Packages”字段列出的包名及 MIT 声明采用，删除精确版本映射和额外哈希记录；未知缺失文本仍使构建失败，包自带新原文始终保留。比较版本及固定链接只说明来源依据，升级按上游许可和发行材料维护，不逐文件审计 npm 源码。相同的 uiw 原文保留一次；mitt 的 MIT 链接和作者声明原文与项目补充的标准条款分开列明，版权年份不作推定。VuePress 的客户端构建采用相同插件；原有 Dashboard 模板许可单独加入。
- JDK 派生转换改为调用 Long.toUnsignedString 与 BigInteger 公共 API，避免复制实现；以极值及随机数对照原数值语义。
- 前端另纳入 Vite、Vue/React 插件辅助代码和 Tailwind/UnoCSS 样式生成器的实际安装版本许可，覆盖由工具注入而没有普通模块 ID 的代码与预置样式。
- 逐文件核对固定上游快照：Spring Boot Admin 使用源码注释中的提交；MIT 来源将上游全文与项目 Apache 修改声明区分，并让所有分发归档携带各许可证。比较快照不自动视为历史首次引入版本；上游作者仅记录为来源归属。
- AudioFlvTag 的三个网页 HTML 表格与已有枚举值重复，以简体中文说明枚举用途，保留数据和参考链接；不通过删除注释宣称整个枚举的历史来源问题已清除。
- 五个 jt-framework 工具类复用自 hylexus 在该项目中编写的代码，按本项目 Apache-2.0 许可提供；其他仓库的贡献状态不推定到这些文件。从 Gitee 固定提交核对 matrixy、ldming、sky 的实际源码及许可，不只依据仓库元数据；jump3r 依据上游包级许可和发行材料维护，具体声明疑问单独记录。仅有参考链接不自动等于复制，无可核实源码的内容保留明确待办。

- 新标志采用自行绘制的几何矢量路径，保留彩色标志源文件、单色/字标版本和可重现的尺寸导出脚本。同步文档、各前端 public 资源、内联 Dashboard 标志及 IDE 图标，不将原截图和示意图推定为新作。
- 标志使用等宽、镜像的双向通道，蓝色撇在下、青色捺在上，保留交叉留白。Python 标准库脚本按几何参数生成 `mark.svg`。导出脚本先运行该生成器，再同步单色、字标图形、Dashboard 内联组件、SVG 副本及位图导出。单色版通过遮罩保留透明间隙。来源说明记录对旧版交错箭头风格的参考范围。

- 剩余简单图形直接编写 SVG 替换，保留拖拽含义和首页背景用途，删除 public 中不再使用的旧背景，避免继续随站点分发；截图和复杂示意图单独列明，不扩大新资源声明。
- 依赖许可检查保留一个政策来源：`allowed-licenses.json`。`enforceLicenses` 委托 `checkLicense`，报告渲染器使用接口类型数组。依据上游元数据按 Apache/MIT/BSD/Bouncy Castle/EPL 等类别及别名匹配，移除普通依赖的逐版本人工白名单；不全局允许 GPL/LGPL，不把机器匹配视为法律结论。
- Boot 保留上游嵌套 JAR 的许可资源；Shadow 合并同名声明。参考 Spring Boot CLI 的集中组织方式，将 Bouncy Castle、Protobuf、OnGres、RoaringBitmap 和 EPL 的必要补充原文保存在单份 `licenses/jvm/open_source_licenses.txt`，保留来源和双语范围说明；各应用共用，各节仅适用于实际包含的组件。打包复制为 `META-INF/open_source_licenses.txt` 并追加实际 EPL 依赖的源码下载地址，普通库不附带汇总。材料检查核对汇总原文；无逐版本补充映射、逐源文件哈希、类路径哨兵或二进制锁定，不要求逐文件审查依赖内部源码。
- OnGres common 的补充直接采用上游发布的包级 BSD、Bouncy Castle 许可和运行时 NOTICE 摘录，不将其作为重新审计内部源码的项目。

- RoaringBitmap 的 LICENSE、AUTHORS 及简短来源原文共同补充；AUTHORS 表示上游归属，不表示参与本项目开发。共享文本仅复制一次，普通库不附带。

## Risks / Trade-offs

- 复制源码的七份完整原文集中于 `licenses/source/open_source_licenses.txt`，用原文件名作分节标识；许可头任务从该文件提取对应原文，不改变现有版权和许可头。所有 Java 归档只携带此汇总，不携带审查 JSON。固定比较来源及限制保留在现有说明，删除 provenance.json 及重复哈希清单；合并不表示解决已有来源疑问。LGPL-2.1 和 MPL-2.0 全文继续单独保留，前端与 JVM 的现有轻量组织不变。

- 应用为实际版本的 Logback、Jakarta Annotation API 和 AspectJ Weaver 提供完整对应源码的 Maven Central URL，明确 EPL-2.0 选择，保留上游原许可和声明。缺少可阅读许可的 Logback 补充官方 EPL-2.0 全文，不再下载、复制整份 EPL 源码包。
- JVM 项目说明继续中英对照；删除独立依赖的 reviewed.json、源码头索引、分目录补充材料及映射，不把同样的审查负担移到别的目录。共用汇总不是完整依赖清单，列出某组件不代表每个应用都包含它。升级依据上游许可、变更记录和发行材料更新适用段落，没有逐版本人工放行门禁；具体矛盾、依赖修改及重新打包另行调查。
- 分发核对脚本检查实际归档的项目原文、复制源码材料、应用必要补充、EPL 源码地址和 ZIP 路径唯一性；ADPCM/jump3r 的特殊要求保留。元数据政策改为本地或手动 workflow 显式运行，日常 CI 运行材料检查。
- 图片内嵌数据提取到本地构建目录，预览清单用于维护者核对；存在源图、软件元数据或 Git 提交记录均不独自证明原创。删除确认未引用的 Vite 图标后核对生产产物。

- NOTICE 和 THIRD-PARTY-SOURCE-NOTICES.txt 的项目说明以完整句子或完整意思为单位做中英对照，每组之间空行；英文保持原意，版权行、名称、标识符、路径和 URL 保留原样。逐文件对应关系使用中英字段标签，字段值只列一次。Spring Framework/Boot 转载声明和 G711 源码头引用整体保留，不在原文中插入翻译。上游作者归属另明确说明不是本项目贡献者名单，尚未核实的范围也同步翻译；不新增语言优先规则。
- THIRD-PARTY-FRONTEND-NOTICES.txt 的双语说明在共享 Vite 插件维护，由八个前端的生产构建生成。标题、自动生成提示、收集范围、许可边界、分发要求采用中文在前、英文紧随；许可和补充来源字段使用中英标签。补充来源记录中的项目自写说明同步翻译，包名、版本、路径、URL 和上游许可/版权/免责原文保留。核对改动前后的全部汇总，验证正文未丢失及后端复制传播，不手工编辑 dist 文件。
- 前端保留根 Apache LICENSE、简短项目归属、适用模板和显式静态资源材料，不再无条件附带根后端 NOTICE、后端源码声明及 licenses/source 全文。`licenses/frontend/NOTICE.txt` 保留根 NOTICE 开头的项目名称、URL 和版权，由收集器测试核对一致。docs 未引用已确认派生类的源码片段；后续引入时须显式补充适用声明。npm 许可正文仅按完整文本一致去重，各包名称、版本、原文件路径、补充来源及文本引用仍逐项保留；相同 SPDX 名称但版权或条款不同的正文分别保留。工具注入的辅助代码和样式许可仍纳入，不因其属于开发依赖而直接删掉。
- Gradle 前端任务的共享许可输入同步收窄到生成器、类型声明、licenses/frontend 和根 LICENSE；不再把后端来源文件及整个审查脚本目录作为输入，避免无关文档更新触发 UI 重编。各前端源码、public、模板及原有附加输入仍保留。
- 文档声明页集中维护中英项目状态、免责与第三方商业承诺说明，并链接 Apache-2.0 第 6～9 节。根 README 顶部与文档首页提供商用摘要和入口，根 NOTICE 与 frontend/NOTICE 共用简短前缀并链接到声明页。现有测试核对前缀一致，项目原始许可和上游归属原文保持完整。
- README 和文档首页摘要同样醒目表明可依适用许可证自由使用、修改、再分发及商用。完整说明及根/前端 NOTICE 明确无需另行取得本项目作者的商业授权，列明仍须履行适用的版权、许可、归属、修改说明及源码提供等义务；不承诺第三方材料适用同一许可，不把“无需商业授权”误写成无须遵守许可证。只更新文字，沿既有打包流程验证传播。
- Spring 类比仅置于完整声明页：限定为按 Apache-2.0 发布的 Spring Framework 代码，说明遵守许可证即可行使其授予的权利，无需另行购买商业授权；独立购买的支持和服务按另行约定处理。使用该依赖不会自动带来官方背书，也不会自动转移使用者自身代码和商业承诺的责任。中英例子以适用法律、许可证及另行约定为边界；不在 NOTICE 或 README 摘要重复展开，不将其表述为 Spring 官方意见。
- 声明页说明可如实注明“本项目使用了 xtream-codec”并附项目链接，宣传应准确说明与项目的关系。适用的版权、许可和归属要求见各许可证。
- 代表性 Boot 和 Shadow JAR 中的前端许可汇总直接与同次构建生成的 dist 文件逐字节比较。
- docs 字体保持 Font Awesome Free 6.7.1，使用 npm 官方固定包中三个 WOFF2 的原始字节，沿用现有本地文件名和 CSS 引用。字体目录的双语 README.txt 保留版本、官方来源、归档成员、OFL 适用范围和分发条件，随 public 目录复制并显式纳入 docs 汇总，上游完整复合 LICENSE 原文保留。移除 static-assets.json 及固定字体、许可审查哈希门禁，升级时同步更新来源说明和原始许可。
- 八个前端由标准库 Python 脚本统一调度，复用既有产物核对函数及前端收集器检查。默认逐项执行 pnpm install --frozen-lockfile 和生产构建，日志保存在忽略的 build 目录；任一步失败返回非零状态，缺失产物不跳过。docs 根据 CSS 中的 WOFF2 引用核对仓库与站点副本，LICENSE/README 全文必须出现在汇总，两个 Dashboard 保留模板许可。提供 --skip-install 和 --check-only 供本地明确选择，后者不证明重新构建。CI 使用无跳过参数的同一脚本，保留 JVM 归档核对，独立依赖政策仅在手动 workflow 时运行。

- [缓存版本不等于最初复制版本] → 记录核对版本及限制，保留现有来源与修改说明，不虚构精确复制版本。
- [前端和音视频来源核实仍有缺口] → 审查文档列出具体文件、验证依据及下一步，不宣称完整合规。
- [Shadow 对许可文件转换遗漏] → 验证实际归档中的项目与依赖声明、同名路径内容，并核对任务依赖。
