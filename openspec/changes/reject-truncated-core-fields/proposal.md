# Proposal

## Why

核心模块在字段数据不足时，普通解码可能返回 null 并继续处理剩余字节，跟踪解码则抛异常。集合中残留的半个字段还可能被当成下一条元素，用户已确认统一为必需字段数据不足即失败。

## What Changes

- **BREAKING**：普通模式对缺失或截断的必需字段抛出 IndexOutOfBoundsException，与跟踪模式保持一致。
- 条件不成立的字段继续跳过；合法零长度字段及读取剩余输入的字段继续使用各自编解码器的空值语义。
- 补充固定长度、长度前缀、嵌套和集合的回归测试，确认失败时停止读取。
- 将 JT/T 808 的 0x0608 空数据列表及 0x8800 零重传包数组断言同步为字段编解码器的空内容结果，并使用提交前脚本的全部参数验证整个仓库。

## Capabilities

### New Capabilities

- `core-field-decoding`：定义注解驱动核心解码中必需字段数据不足、条件跳过和合法空内容的行为。

### Modified Capabilities

无。

## Impact

修改 BasicBeanPropertyMetadata 的普通字段解码入口、核心回归测试及两处 JT/T 808 空内容断言，不新增依赖。既有依赖截断输入返回部分对象的调用方需要改为提供完整报文，或通过字段条件明确表达字段不存在。合法空列表和空字节数组由对应字段编解码器返回，不再由普通入口提前替换为 null。
