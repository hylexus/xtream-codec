# Design

## Context

参见 proposal.md。BasicBeanPropertyMetadata 的普通入口在没有数据或不足声明长度时提前返回 null；跟踪入口始终提取长度并调用字段编解码器。实体及嵌套解码循环在入口调用前计算字段条件。

## Goals / Non-Goals

统一两种模式对必需字段截断的处理，阻止集合将未消费的半个字段重新解释成下一条元素。保持有效报文的值、读取位置、条件分支和跟踪诊断。范围限于现有字节字段解码入口，不改变集合迭代次数语义，不测试废弃 API。

## Decisions

- 普通模式移除提前返回 null 的判断，始终先提取长度、再委托字段编解码器，与跟踪模式采用相同流程。
- 长度提取后，两种入口共用可读长度检查，沿用 IndexOutOfBoundsException。回归测试确认字符串及 ByteBuf 切片在容量充足、已写入数据不足时也可能接受截断输入，不能只依赖字段编解码器的边界检查。
- 检查使用提取长度后的 readableBytes，避免将已消费的前缀计入可用内容；负长度保留读取剩余输入的约定。跟踪模式在长度检查失败时记录失败字段节点，不影响成功路径的节点结构。
- 可读长度检查仅负责校验和抛出异常，不接收跟踪器。跟踪入口只捕获该检查的 IndexOutOfBoundsException，为失败字段创建节点并显式调用 scope.fail 后原样抛出；成功路径仍由字段编解码器创建节点，避免重复记录，也不依赖未完成 scope 关闭时的隐式失败处理。
- 合法空内容与缺少必需数据通过声明长度及字段编解码器区分，不能用输入是否为空统一判断。零长度字节数组、零长度字符串、读取剩余字节的字段均增加对照测试。
- 在实体入口参数化验证普通及跟踪模式，覆盖 POJO、Record、集合中的 Record，精确断言读取位置及集合外尾字段未被消费。
- JT/T 808 集成用例按相同契约断言合法空内容：0x0608 的 count 为零时，自定义字段编解码器返回空列表；0x8800 的重传包数为零时，长度表达式为零，字节数组编解码器返回空数组。仅更新对应断言，保留精确报文验证；最终使用 before-commit.sh 的 clean build 和全部检查参数验证。

## Risks / Trade-offs

- 普通模式不再容忍不完整的必需字段 → 用户已确认此兼容性变化，补充回归测试并记录迁移方式。
- 自定义字段编解码器仍负责其自身读取逻辑 → 通用入口只校验已声明的正长度，不推测负长度字段所需的字节数量。
