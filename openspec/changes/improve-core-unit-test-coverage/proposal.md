# Proposal

## Why

`xtream-codec-core` 的已有测试覆盖了主要编码流程，但部分非废弃的编解码器、工具及边界分支缺少直接验证。补充行为测试，降低后续修改破坏二进制格式、缓冲区状态和异常契约的风险。

## What Changes

- 使用临时 JaCoCo 配置建立核心模块覆盖率基线，按遗漏情况选择测试目标。
- 补充非废弃代码的正常、边界和异常用例，验证输出内容及相关状态。
- 不为 `@Deprecated` 类型、方法和废弃包新增测试。
- 修复新增测试发现且用户确认一并处理的 ASCII 字符串读取类型转换异常，保留回归用例。
- 运行核心模块测试、Checkstyle 和覆盖率对比，记录结果。
- 第二轮补充 Pair/TLV 普通编解码、运行时类型、嵌套 Record 和集合测试，比较普通模式与跟踪模式的字节、结果和索引。
- 修复第二轮测试发现且用户确认一并处理的运行时嵌套编解码版本丢失问题，保留多版本回归用例。
- 第三轮补充 Map 编解码的边界、版本匹配、配置冲突及异常释放测试，以及非废弃的自定义 FieldCodec 构造选择和依赖注入测试。
- 第四轮补充 DictKey 的数值转换、字符集、精确字节和跟踪范围，以及 XtreamBitOperator 的条件重载、回调次数、可变性和位范围边界测试。
- 修复第四轮测试发现且用户确认的 GB2312 字典键返回 GbkString 类型问题，保留普通和跟踪模式的回归用例。
- 第五轮补充 Pair/TLV 扩展元数据的版本、缓存及错误配置测试，以及字段编解码器注册表的描述信息、覆盖注册和类型查找测试。
- 第六轮补充动态表达式结果的有限数值、整数和嵌套深度上限、嵌套集合快照及结果转换测试，以及动态字段定义的字符集、选项边界、派生配置和生成值冲突校验测试。
- 第七轮补充 Record 的基本类型默认值、空值策略与集合隔离，以及派生字段的版本回退、空值、只读逆变换回退和转换异常后继续解码的测试。
- 修复第七轮测试发现且用户确认的瞬态 Record 字段继续解析内部结构的问题，保留基本类型默认值和 Map 空值策略的回归用例。
- 第八轮补充 Record 派生组件无匹配版本及基本类型计算失败的边界、动态字节字段的实际值与填充和字符错误边界，以及类级与字段级属性访问策略的优先级测试。
- 修复第八轮测试发现且用户确认的 Record 派生组件无匹配版本时构造参数不足、基本类型派生值未赋值时拆箱空指针问题，保留回归用例。
- 为反射构造与字段访问测试中刻意保留的构造器、参数及字段添加成员级 Error Prone 警告抑制，验证严格编译和原有测试通过。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

无。本次仅补充已有行为的测试，设置 `skip_specs: true`，不修改产品行为规范。

## Impact

变更涉及 `xtream-codec-core/src/test`、`XtreamByteReader.readString` 的一行修复、`RuntimeTypeFieldCodec` 的四处版本参数传递、`DataField.DictKey.deserialize` 的 GB2312 返回类型修复、`SimpleBeanMetadataRegistry` 的瞬态字段及 Record 组件占位分支、`EntityDecoder` 的 Record 基本类型派生值兜底和本变更记录，不新增正式构建依赖，不调整文档引用示例。
