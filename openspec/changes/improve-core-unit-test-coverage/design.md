# Design

## Context

核心模块使用 JUnit Jupiter、AssertJ 和 Mockito，正式构建没有覆盖率插件。参见 proposal.md 的动机及范围。

## Goals / Non-Goals

验证缺少覆盖的已有行为，包括确定的二进制输出、缓冲区索引、资源释放和非法输入。测试只调用非废弃 API，不为覆盖数字修改生产代码。

新增测试发现 `XtreamByteReader.readString` 将 Netty 的 `AsciiString` 强转为 `String`，用户确认一并修复。改为调用 `CharSequence.toString()`，同时验证直接读取和消费者回调两条路径。

第二轮测试确认 `RuntimeTypeFieldCodec` 的嵌套解码及跟踪编码调用无版本参数的重载，导致更深层对象采用默认版本并跳过版本专属字段。用户确认一并修复：四处委托调用显式传入 `context.version()`，以两个版本、两种模式及有界/剩余输入解码验证。

第四轮测试确认 `DictKey.deserialize(str_gb_2312, ...)` 正确按 GB2312 读取文本，却创建了 GbkString，使类型、名称及声明字符集变成 GBK。用户确认将该分支改为创建 Gb2312String，普通及跟踪模式各保留一个回归用例。

第七轮测试确认 `SimpleBeanMetadataRegistry` 在字段编解码器为 NullFieldCodec 时没有优先处理 TRANSIENT 策略，导致隐式瞬态 boolean 组件被当作嵌套实体解析，显式瞬态 Map 组件进入旧 Map 元数据分支。用户确认一并修复：将 TRANSIENT 策略加入直接保留基本元数据的条件，跳过不参与线上编解码的内部结构解析，并保留 8 个回归用例。

第八轮测试确认 Record 派生组件版本未匹配时被整个移出元数据，导致构造参数数量不足；基本类型派生转换失败或返回 null 时，构造参数仍为 null，调用构造器时拆箱失败。用户确认一并修复：仅为未匹配版本的 Record 派生组件保留瞬态元数据，在调用 Record 构造器前为仍为空的基本类型派生参数补入对应零值。引用类型仍保留 null，POJO 行为不变。

第九轮测试确认 EntityEncoder 的 Iterable 跟踪分支缺少整批操作边界，导致根报文只包含最后一个实体、纯 DataField 列表方向未设置、失败偏移以当前元素起点计算。用户确认一并修复：仅在该分支按 rootInvocation 统一开始、完成和记录失败，已有外层跟踪时继续使用外层边界，普通编码及写入字节不变。

第十三轮测试确认 DataWrapperFieldCodes.INSTANCE_STRING_UTF_8 错误声明并初始化为 DwordWrapperFieldCodec，导致 StringWrapperUtf8 字段在两种模式下解码为整数包装类型，调用 Record 构造器时报类型转换异常。用户确认将该公开常量的声明类型及初始化对象同时更正为 StringWrapperUtf8FieldCodec，保留注册器检查和两种模式的回归用例。

第十五轮测试确认瞬态字段注解代理对外返回 TRANSIENT，但内部默认属性仍为 DEFAULT，造成等价代理不相等、与真实注解比较不对称及展示错误；version 数组还按对象身份计算哈希，导致 HashMap 查询失败、HashSet 重复保存等价注解。用户确认仅统一内部有效策略，并按 int[] 内容计算哈希；保留 9 个失败后转绿的回归用例，不调整公开 API 或线上编解码行为。

第十六轮测试确认 DictJsonDeserializer 构造 Dict 时丢弃 name 及扩展属性；value 缺失时报空指针，传入 null、数组或标量则静默创建空字典。用户确认仅修改该反序列化器：按已有 JsonAnyGetter 格式保存展开的扩展属性（排除 type、name、prependLengthFieldType、keyType、valueLengthType、value），保留自定义名称，缺省或显式 null 名称仍回退为 Dict；要求 value 为 JSON 对象，否则抛出明确的 JsonParseException，合法空对象继续接受。保留 28 个失败后转绿的回归用例，并验证扩展属性内的 null、列表及嵌套对象。

## Decisions

- 临时 Gradle init script 启用 JaCoCo，保存修改前后的 XML 和 HTML 报告，正式构建不增加插件。
- 优先覆盖独立且缺少测试的工具及字段编解码行为，再依据报告补充较大遗漏分支。
- 使用固定输入和精确结果断言；涉及 Netty 缓冲区时使用 `finally` 释放，不依赖默认时区或随机数据。
- 第二轮以第一轮报告为基线，优先补齐普通编解码路径和嵌套 Record 专用解码路径；参数化覆盖普通模式及跟踪模式，并在非零起始偏移下检查索引与跟踪范围。
- 第三轮针对 Map 测试精确字节、未知键回退、字符串键填充、有界截断、元数据版本优先级与冲突和异常释放；通过最小自定义 FieldCodec 夹具验证构造器选择、注册器参数注入及 FieldCodecRegistryAware 回调，不测试废弃的 BeanMetadataRegistryAware 路径。
- 第四轮以固定十六进制数据验证 DictKey 数值及字符串键的转换、类型、字符集、字节和索引；对位操作的布尔值、Supplier 和 Predicate 条件重载分别验证执行和跳过、回调次数、对象身份及第 63 位和完整 64 位范围。
- 第五轮通过真实 Pair/TLV 字段注解验证扩展元数据的必需配置、版本选择、字段缓存及 Pair 长度约束，直接验证匹配器的重复配置和字符集回退；使用隔离的字段编解码器注册表验证描述信息与实际查找的一致性、覆盖注册及未注册原子类型的错误，不测试废弃编解码器。
- 第六轮通过公开动态计划入口验证表达式引擎结果的数值与深度上限、嵌套 List/Map 的独立只读快照及精确 JSON 数值转换；对失败结果断言字段路径、位偏移、读取索引和跟踪诊断。通过字段构造器和 JSON 导入对照验证字符集、选项类型与范围、派生配置及生成值互斥规则，同时保留合法边界用例。
- 第七轮通过默认值工具入口验证基本类型和两种 nulls 策略，通过真实 Record 解码验证隐式瞬态组件、条件跳过、显式空容器和两次解码之间的集合隔离。以真实派生字段注解和最小转换器验证精确版本优先、默认版本回退、版本不匹配、只读转换器逆变换回退及转换异常不影响后续字段；对照普通和跟踪模式，并检查精确字节、对象源值及读取索引。
- 第八轮用真实 Record 验证无默认版本的派生组件和基本类型转换失败时的构造参数；动态字段通过公开计划验证 byte[]、非法列表元素、两侧填充剥离及严格字符集错误，并核对精确字节、字段位置和读取索引；属性访问通过真实实体注解和可区分的 getter/setter 验证覆盖、继承与 AUTO 选择。若复现需要改变生产行为的问题，先记录证据并确认处理范围。
- 覆盖率对比同时说明模块原始统计和废弃代码的影响，避免将未测试的废弃 API 作为本次测试目标。
- 反射测试夹具的构造器签名、未使用参数及无 getter/setter 的字段属于测试输入，仅在相应构造器或字段上抑制 UnusedMethod 和 UnusedVariable，并用中文注释说明反射用途，保留项目级检查规则和测试行为。
- 第九轮通过真实实体字段验证 EncodedLength 的 u8/u16 临界容量和超限异常、条件跳过、空范围以及非零缓冲区偏移；通过 EntityCodec 公开入口验证 Iterable 中多个实体、DataField 和混合元素的精确拼接、版本传递、空列表与异常停止，并检查整批跟踪的节点及相对偏移。若测试暴露行为缺陷，先记录复现并明确修复范围。
- 第十轮通过 DynamicPlan 公开入口对照普通与跟踪编码，检查容器前缀容量、完整字节、固定长度及集合计数错误，并验证错误字段路径、位偏移、部分输出与尾字段停止；通过 CodecTracker 公开作用域验证临时缓冲区的嵌套和异常恢复、checkpoint 封存范围及非零起点与 slice 坐标组合，并用记录器无显式范围的叶节点观察逐层游标恢复，不扩展到 Tracker 跨操作复用契约。
- 第十一轮直接验证 CodecTraceValueRenderer 的值与摘要，保留标量类型，核对非废弃包装类型的有符号/无符号值、字符串和字节转换；以独立期望验证 119/120/121 字符摘要，并通过真实 Trace 节点、视图和 Jackson 检查 JSON 类型及完整值，使用字节数组验证转换结果与输入隔离。仅覆盖现有公开行为，不为不可达或废弃路径构造夹具。
- 第十二轮通过真实 ObjectMapper 和现有序列化注解验证调试 JSON，分别检查包装值、原始字节字段和对象／列表中的输出，保留该序列化器已有的有符号字节表示；用独立包内的公开注解夹具验证类／字段／方法扫描、组合去重、过滤、子包及相似包名前缀隔离，避免依赖业务示例或扫描结果顺序。
- 第十三轮以独立 HEX 断言包装类型的 writeTo、asBytes 和 length，验证整数转换、指定字符集、空值和 setValue 后的状态；通过 EntityCodec 公开入口对照普通与跟踪模式，确认默认注册器使用非废弃实现。长度字段按七种类型验证独立读写及跟踪读写，使用非零缓冲区起点并检查输入不足时的读取索引；若测试暴露需要改变生产行为的问题，记录复现并确认修复范围。
- 第十四轮通过公开扩展字段 options 验证 Map/List 多层配置的复制隔离、逐层只读、顺序及数值类型保真，并使用真实扩展计划确认原始配置修改不影响编解码。表达式定义通过 Java 构造与 JSON 导入对照验证来源和引擎绑定规则、运算参数数量及集合隔离；以独立计数确认深度 32 和节点数 4096 的合法边界及刚好超限，分别隔离两种复杂度限制。只验证已有契约，不与表达式运行结果的资源限制测试混用。
- 第十五轮通过公开瞬态注解代理入口与真实 XtreamField 注解对照，验证有效属性、自反／对称／传递性、相等对象的哈希值、数组值语义和 HashMap／HashSet 使用；使用独立字段避免污染既有元数据缓存。XtreamMethodParameter 使用真实反射方法验证相同方法位置的缓存命中、重载及声明类和返回槽区分、合法与非法索引、泛型查询位置以及组合注解属性。新增用例若确认行为缺陷，保存复现并明确最小修复范围。
- 第十六轮通过 DataFields 公开入口对照 JSON 字符串与对象、单字段与列表转换，明确断言类型别名、数值及字节、嵌套顺序、字符集、填充和长度配置；序列化按现有 JsonAnyGetter 格式将 attributes 展开为扩展属性。使用独立 HEX 验证解析后的普通及跟踪编码，单独验证字典自定义名称和扩展属性的保留。非法输入分别检查字符串入口的异常包装和对象入口的失败原因，避免依赖完整的 Jackson 错误文本；若发现行为缺陷，保存复现并确认最小修复范围。

## Risks / Trade-offs

- 全模块比例包含废弃代码和生成代码 → 交付总体趋势以及本次目标类型的指标，明确统计口径。
- 往返测试可能掩盖对称错误 → 对编码结果增加独立的字节断言。

## 第十七轮：构造参数与嵌套路径组合

- 先保留失败回归，再修复已复现问题：Record 调整编码顺序后构造参数错位、静态常量造成属性空项、集合 Record 的基本类型默认值缺失，以及嵌套 POJO 的 EncodedLength 未回填。
- 属性列表与 propertyIndex 继续采用编码顺序，在 Record 构造边界转换到组件声明顺序；Record 属性扫描按组件名定位字段，排除静态常量。
- 集合元素的 Record 解码委托给已有 EntityDecoder，统一条件、瞬态和派生字段的默认值语义；仅在嵌套对象存在 EncodedLength 时委托已有 EntityEncoder，复用长度统计与跟踪回填。
- 用非零缓冲区起点、独立 HEX、尾随字节、完整对象比较和普通／跟踪双模式验证上述行为。实体元数据缓存使用独立注册表和同步起跑的并发调用，不依赖调度顺序或休眠。
- 动态扩展异常检查字段路径、位偏移、原始原因、游标及引用计数，并验证同一计划后续调用仍可成功；精确整数在公开计划入口验证 JSON 安全整数阈值、BigDecimal 和非法数值。

## 第十八轮：长度边界与重复调用

- 嵌套 Record 解码遵守字段的固定长度、表达式长度和前置长度，按已有嵌套 POJO 的方式使用非持有切片；有界区域不足时报错，不读取外层尾字段。跟踪模式在切片内使用坐标作用域，并验证非零起点、多层嵌套及异常位置。
- `iterationTimes` 按现有注释作为最大次数，默认仍为 1024。分别验证有界区域在达到次数后消费整个区域、无界输入保留剩余字节、零消费元素仍受到次数限制，以及显式提高上限可以读完 1025 项；不改为严格计数或改变默认值。
- 内省缓存按实体类和字段过滤器区分，禁用缓存时同时绕过缓存读取与写入。使用并发 Map 发布缓存结果，不扫描原本未选中的字段，避免扩大反射访问范围；相同过滤器对象可以复用，不尝试判断两个不同 Predicate 是否语义等价。
- POJO 解码条件不满足时保留实例原有字段及派生值，表达式变量仍按现有路径设置为空；通过同一对象先成功解码、再跳过、最后再次满足条件的过程验证状态、派生回调及后续编码，避免在补测试时引入重置行为。
- 本轮先运行失败回归，再完成最小修复；对照普通与跟踪模式，检查精确字节、读取索引、引用计数和 Trace。

## 第十九轮：属性方法选择与动态数值边界

- setter 候选必须能接收字段类型，兼容基本类型的装箱形式；精确字段类型优先于宽泛参数，相同参数类型保留先扫描的子类实现。以继承、重载、链式 with 方法及字段回退验证描述符，再通过真实 EntityCodec 验证普通和跟踪解码。
- 派生位段先按无符号位模式合成，再依源整数的有符号位宽还原补码；显式源值仍遵守原有范围校验。覆盖符号位、完整位宽、部分输入、重叠一致及冲突和非法位段，并核对独立 HEX、错误路径、偏移及部分输出。
- 动态浮点通过公开计划验证双字节序下的正负零、次正规数和有限边界，拒绝 NaN、正负无穷和转为 f32 后溢出的有限 double。编码失败保留已写前缀，解码失败不提交调用方 readerIndex；普通与跟踪模式分别验证诊断和引用计数。
- 先保存失败回归证据再修改生产代码，最后执行 core 全量检查、core-debug 回归和覆盖率对比。

## 第二十轮：动态编译边界与回填值传递

- 位段范围必须处于源整数位宽内，使用 long 计算偏移与宽度之和，避免两个合法 int 相加溢出而通过编译。对照 Java 定义及 JSON 导入，覆盖最大 int、刚好越界、完整位宽及末位合法值；验证小端 msb0 跨字节限制和 lsb0 的合法对应场景。
- 嵌套结构与数组元素中的长度字段以最终回填值提供给后续表达式和 Tracker，忽略调用方提交的错误长度值。验证各元素独立回填、条件字段跳过、空内容以及长度字段本身跳过时的既有语义，检查输入不被修改、精确 HEX 和非零缓冲区起点。
- 版本筛选先于引用及布局验证。数组元素被排除时报编译错误，整个集合被排除时不检查其元素；choice 分支被排除后按有效默认分支处理，无分支时在执行期报告缺失分支。分别验证保留空结构的情况、尾字段、读取索引与普通／跟踪失败诊断。
- 先保存范围溢出的失败测试，再做一行生产修复，最后执行完整回归和静态检查并更新覆盖率记录。

## 第二十一轮：缓冲区生命周期与动态失败状态

- ByteBufContainer 的字节数组、数值、BCD 和字符串工厂仅在创建容器时分配缓冲区，统一委托已有的 ofBytes(ByteBuf) 持有该对象，使 payload、读取、写入及 release 作用于同一缓冲区。保持已有写入消费 readerIndex 和不额外 retain 的语义；数值视图从当前 readerIndex 读取，与 length 和 asBytes 一致。
- 动态计划使用直接及复合输出验证长度和 CRC 回填，输入覆盖堆、直接、跨组件复合、切片及只读视图。核对精确 HEX、校验和、非零起点、父子索引隔离及引用计数，并用损坏报文验证严格校验失败不提交 readerIndex。
- bits 的缺省、类型、长度和非法字符输入分别验证拒绝位置，非法字符之前的位允许保留为部分输出；countOf 的目标缺失、null 或非 List 时在计数字段失败。普通与跟踪模式核对路径、位偏移、已写内容和尾字段停止，并验证同一计划后续调用可以成功。
- 先保存容器缺陷的失败回归，再做局部修复；完整执行 core 检查、core-debug 回归和覆盖率对比，保留前轮未提交改动。

## 第二十二轮：动态长度、描述输出和表达式编译失败
