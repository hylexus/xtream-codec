# Design

## Context

核心模块使用 JUnit Jupiter、AssertJ 和 Mockito，正式构建没有覆盖率插件。参见 proposal.md 的动机及范围。

## Goals / Non-Goals

验证缺少覆盖的已有行为，包括确定的二进制输出、缓冲区索引、资源释放和非法输入。测试只调用非废弃 API，不为覆盖数字修改生产代码。

新增测试发现 `XtreamByteReader.readString` 将 Netty 的 `AsciiString` 强转为 `String`，用户确认一并修复。改为调用 `CharSequence.toString()`，同时验证直接读取和消费者回调两条路径。

第二轮测试确认 `RuntimeTypeFieldCodec` 的嵌套解码及跟踪编码调用无版本参数的重载，导致更深层对象采用默认版本并跳过版本专属字段。用户确认一并修复：四处委托调用显式传入 `context.version()`，以两个版本、两种模式及有界/剩余输入解码验证。

第四轮测试确认 `DictKey.deserialize(str_gb_2312, ...)` 正确按 GB2312 读取文本，却创建了 GbkString，使类型、名称及声明字符集变成 GBK。用户确认将该分支改为创建 Gb2312String，普通及跟踪模式各保留一个回归用例。

第七轮测试确认 `SimpleBeanMetadataRegistry` 在字段编解码器为 NullFieldCodec 时没有优先处理 TRANSIENT 策略，导致隐式瞬态 boolean 组件被当作嵌套实体解析，显式瞬态 Map 组件进入旧 Map 元数据分支。用户确认一并修复：将 TRANSIENT 策略加入直接保留基本元数据的条件，跳过不参与线上编解码的内部结构解析，并保留 8 个回归用例。

第八轮测试确认 Record 派生组件版本未匹配时被整个移出元数据，导致构造参数数量不足；基本类型派生转换失败或返回 null 时，构造参数仍为 null，调用构造器时拆箱失败。用户确认一并修复：仅为未匹配版本的 Record 派生组件保留瞬态元数据，在调用 Record 构造器前为仍为空的基本类型派生参数补入对应零值。引用类型仍保留 null，POJO 行为不变。

## Decisions

- 临时 Gradle init script 启用 JaCoCo，保存修改前后的 XML 和 HTML 报告，正式构建不增加插件。
- 优先覆盖独立且缺少测试的工具及字段编解码行为，再依据报告补充较大遗漏分支。
- 使用固定输入和精确结果断言；涉及 Netty 缓冲区时使用 `finally` 释放，不依赖默认时区或随机数据。
- 第二轮以第一轮报告为基线，优先补齐普通编解码路径和嵌套 Record 专用解码路径；参数化覆盖普通模式及跟踪模式，并在非零起始偏移下检查索引与跟踪范围。
- 第三轮针对 Map 测试精确字节、未知键回退、字符串键填充、有界截断、元数据版本优先级与冲突和异常释放；通过最小自定义 FieldCodec 夹具验证构造器选择、注册器参数注入及 FieldCodecRegistryAware 回调，不测试废弃的 BeanMetadataRegistryAware 路径。
- 第四轮以固定十六进制数据验证 DictKey 数值及字符串键的转换、类型、字符集、字节和索引；对位操作的布尔值、Supplier 和 Predicate 条件重载分别验证执行和跳过、回调次数、对象身份及第 63 位和完整 64 位范围。
- 第五轮通过真实 Pair/TLV 字段注解验证扩展元数据的必需配置、版本选择、字段缓存及 Pair 长度约束，直接验证匹配器的重复配置和字符集回退；使用隔离的字段编解码器注册表验证描述信息与实际查找的一致性、覆盖注册及未注册原子类型的错误，不测试废弃编解码器。
- 第六轮通过公开动态计划入口验证表达式引擎结果的数值与深度上限、嵌套 List/Map 的独立只读快照及精确 JSON 数值转换；对失败结果断言字段路径、位偏移、读取索引和跟踪诊断。通过字段构造器和 JSON 导入对照验证字符集、选项类型与范围、派生配置及生成值互斥规则，同时保留合法边界用例。
- 第七轮通过默认值工具入口验证基本类型和两种 nulls 策略，通过真实 Record 解码验证隐式瞬态组件、条件跳过、显式空容器和两次解码之间的集合隔离。以真实派生字段注解和最小转换器验证精确版本优先、默认版本回退、版本不匹配、只读转换器逆变换回退及转换异常不影响后续字段；对照普通和跟踪模式，并检查精确字节、对象源值及读取索引。
- 第八轮用真实 Record 验证无默认版本的派生组件和基本类型转换失败时的构造参数；动态字段通过公开计划验证 byte[]、非法列表元素、两侧填充剥离及严格字符集错误，并核对精确字节、字段位置和读取索引；属性访问通过真实实体注解和可区分的 getter/setter 验证覆盖、继承与 AUTO 选择。若复现需要改变生产行为的问题，先记录证据并确认处理范围。
- 覆盖率对比同时说明模块原始统计和废弃代码的影响，避免将未测试的废弃 API 作为本次测试目标。
- 反射测试夹具的构造器签名、未使用参数及无 getter/setter 的字段属于测试输入，仅在相应构造器或字段上抑制 UnusedMethod 和 UnusedVariable，并用中文注释说明反射用途，保留项目级检查规则和测试行为。

## Risks / Trade-offs

- 全模块比例包含废弃代码和生成代码 → 交付总体趋势以及本次目标类型的指标，明确统计口径。
- 往返测试可能掩盖对称错误 → 对编码结果增加独立的字节断言。
