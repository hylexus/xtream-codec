# Design

## Context

动机见 `proposal.md`。当前 `draft-store.ts` 在 IndexedDB 的 `session` 存储中读写固定键 `current`；`app.tsx` 在工作区变化后延迟 350ms 备份，并在页面隐藏时写入。工作区数据已包含报文标签、原文、运行快照和保存基线。

`api.ts` 把所有失败响应转成普通 Error，丢失 HTTP 状态。`saveDocument` 已捕获提交快照，并使用 `acceptSave` 保留保存期间的新编辑。后端 `WorkspaceService.update` 校验 `expectedRevision`，过期返回 409；GET 可取得完整文档。现有 `WorkspaceDialog` 支持单一异步提交，保存并关闭流程等待提交完成后继续关闭队列。

本变更涉及草稿归属和迁移，以及保存、弹窗、异步请求与关闭队列之间的状态协调，因此需要此设计。现有 Studio 规格仍位于已完成但未归档的 `upgrade-codec-studio-workspace`；新增能力规格不改写其内容。

## Goals / Non-Goals

**Goals:**

- 通过独立的可写草稿记录实现页面隔离，并兼容刷新、浏览器复制标签页及现有恢复体验。
- 以现有条件更新合同完成用户主动选择的覆盖，明确保存基线与异步响应的归属。
- 在普通 HTTP 访问和 React StrictMode 下保持初始化行为一致。

**Non-Goals:**

- 自动合并、实时同步、版本差异编辑器、草稿历史选择及自动清理历史恢复记录。
- 拆分站点级主题和布局偏好，或增加忽略版本检查的后端接口。
- 为目录重命名、移动、删除等元数据操作增加同类覆盖弹窗；本次处理已保存报文的内容保存冲突。

## Decisions

### 1. 页面每次加载创建独立的可写记录

IndexedDB 继续保存完整 Session，采用 `workspace:<uuid>` 独立记录；sessionStorage 的 `xtream-codec-studio-session-id` 保存本浏览器标签页最近使用的记录 ID。每次页面加载先读取该指针对应的快照，再复制到新的随机记录，成功后更新本页指针；之后所有自动备份及隐藏备份只写新记录。UUID 复用现有兼容普通 HTTP 的 `randomUuid`。

关键点是 sessionStorage 指针用于寻找恢复来源，而不直接决定新页面的可写归属。浏览器复制标签页可能复制 sessionStorage，但新页面第一次写入前已经创建新记录；原页面继续使用自己的记录，两者不会共写。刷新也经过同一复制流程，不需要判断页面到底是刷新还是复制。

初始化通过页面模块内的单个 Promise 共享结果，避免 StrictMode 的重复 effect 创建多个当前记录或让迟到的初始化结果覆盖新状态。读写归属在初始化后固定，调用方不能临时切换到其他记录。

备选方案：直接用 sessionStorage ID 读写同一记录会在浏览器复制标签页后发生碰撞；BroadcastChannel 或锁协议增加页面存活探测和后台页面协调；把整个 Session 放入 sessionStorage 会让大型 Trace 受到同步写入和容量限制。因此采用读取来源后复制的方案。

### 2. 最近备份指针仅用于没有页面来源的新访问

在原 `session` 存储中新增独立元数据键 `meta:latest-workspace`。每次成功备份在同一个读写事务中更新当前页面的记录和最近备份指针，同一页面的定时及隐藏备份串行提交，避免完成顺序反转。只有 sessionStorage 中没有页面来源的新访问，才读取最近备份并复制；已有本页来源时始终优先读取本页快照。

这是对当前新开页面和关闭后重访仍能恢复最近工作区行为的兼容默认：新页面初始内容可以相同，但其后的编辑和备份各自独立。最近备份指针是共享的初始化入口，不参与已有页面的刷新归属。多个新页面并发初始化仍分别分配新的记录。

已有本页指针但记录缺失、损坏时显示恢复失败，不静默采用其他页面的最近备份。主题、主题色和面板尺寸沿用现有 localStorage 行为。

### 3. 在成功建立新备份前保留旧恢复来源

没有本页来源且没有新格式最近备份时，优先读取旧 IndexedDB `current`；不存在时复用现有旧 localStorage 模式迁移；均不存在时使用默认初始工作区。新记录与最近备份指针在一个事务中提交，再更新 sessionStorage，完成后才启用自动备份。沿用现有对象存储和 Session 格式即可，不需要数据库结构升级。

旧 `current`、旧 localStorage 及复制来源记录保留，不双写旧格式。sessionStorage 或 IndexedDB 不可用、事务失败及配额耗尽时明确提示，保持内存编辑，不启用任何共享可写回退。自动备份状态只有在提交成功后才显示成功。

不在本次自动删除来源记录：仍有页面、浏览器复制或恢复操作可能引用它们。各活动记录只更新最近一次快照；历史来源的保留和容量增长见风险说明。

### 4. 以 HTTP 状态识别保存冲突

API 错误保留 HTTP status 和现有服务器错误文案，保持当前 422 编解码结果的特殊处理。仅已保存报文的 PUT 返回 409 时进入版本冲突流程，随后 GET 同一文档确认服务器版本确已变化；其他错误或未确认的冲突维持错误提示和本地内容。

冲突上下文绑定编辑器 tabId 与服务器 entryId，携带最近读取的服务器文档和发起保存的流程，不从当前活动标签推断目标。弹窗显示服务器名称、版本和更新时间，用清楚的业务文案说明覆盖后果，提供两个操作和取消；通过 HeroUI Modal 支持键盘、焦点和请求期间的按钮禁用。使用专用冲突弹窗，复用现有 UI 风格；不把两个不同语义的异步操作挤入现有单提交表单。

### 5. 双向覆盖均有明确提交边界

- **使用服务器版本**：确认后再次 GET 最新文档，成功解析后一次性替换目标标签的 DocumentData、entry 元数据、revision 和保存基线，保留 tabId、固定状态与顺序。不发送 PUT。请求失败、目标已关闭或 entryId 已变化时不修改其他标签。
- **用本地版本覆盖服务器**：确认时捕获目标标签当前 DocumentData，以弹窗展示的服务器 entry 的 revision 作为 `expectedRevision` 提交现有 PUT。沿用该服务器 entry 的名称及目录，避免内容覆盖意外恢复旧元数据。成功后复用 `acceptSave` 更新版本和已提交快照的基线，继续保留请求期间的新编辑。
- **再次冲突**：GET 新版本，更新弹窗并要求重新选择；不得自动带上新 revision 重试。404、读取失败或写入失败均保留本地内容与原保存基线，展示原因，不自动创建报文。
- **取消**：不写服务器、不替换本地、不升级保存基线，结束本次保存尝试。

后端不增加 force 参数或新写入路径。读取最新 revision 后直接自动重试会把前一次确认扩大到用户没有确认的版本，因此不采用。

### 6. 替换内容使旧异步运行失效，关闭流程等待明确结果

为编辑器标签维护不持久化的内容替换代次；开始运行时捕获代次，采用服务器版本后递增。旧代次的编解码结果不再写回，即使 tabId 相同，也不能覆盖新采用的 HEX 和运行快照。普通运行中的输入修改继续沿用当前 `completeRun` 规则。

保存流程区分成功、取消和失败。快捷键、工具栏和保存后关闭复用同一冲突处理：关闭队列在冲突期间暂停，成功且目标无新编辑后才继续；取消或失败停止剩余关闭。现有保存后关闭确认框与冲突弹窗串行呈现，避免叠加 Modal 或错误关闭原确认流程；重复保存同一文档不会发出并行覆盖请求。

## Risks / Trade-offs

- 页面加载会保留来源记录，可能增加本地占用 → 复用记录仅保存最近快照，暂不自动删除可能仍被引用的来源；配额错误明确提示且保留现有数据，后续清理需独立设计。
- 最近备份入口仍由最后一次成功备份决定 → 只影响没有本页来源的新访问；已有页面始终按自己的来源恢复，不丢弃其记录。
- 浏览器关闭时最后的异步写入可能尚未完成 → 保持自动备份与隐藏备份，恢复保证针对已成功提交的快照，不承诺浏览器强杀前未完成的写入。
- 接受服务器内容时，旧运行或其他异步响应可能迟到 → 绑定文档身份和替换代次验证，覆盖前后增加回归场景。
- 网络响应丢失可能无法确定 PUT 是否已提交 → 不显示保存成功、不自动重试；保留本地内容，下次保存按服务器实际版本处理。
- 旧版与新版前端并存或回滚时使用不同草稿入口 → 保留所有原始数据，但旧版只能读取原旧格式快照；新版产生的独立草稿不会自动降级写回旧格式。

## Migration Plan

1. 先用同一隔离浏览器上下文中的两个同源页面复现共享 `current` 覆盖，以及已有 HTTP 409 无选择入口的行为，建立回归验证。
2. 实现独立草稿记录、来源复制和旧数据恢复，确保刷新、复制、并发初始化及普通 HTTP 页面均可用。
3. 接入结构化 API 错误、冲突弹窗及双向选择，再验证异步结果与保存关闭流程。
4. 更新 UI README，记录新访问、复制和冲突选择的用户行为及存储失败提示。
5. 在隔离浏览器配置和临时服务器数据目录中验收。实现完成后运行前端检查、必要后端合同测试及 OpenSpec 严格校验；本阶段不归档尚未实现的变更。

如需回滚，仅回退前端；不修改服务器数据结构。保留新旧 IndexedDB 键以便再次升级恢复，明确旧版不会自动读取新版独立草稿，避免把回滚误当成新草稿丢失。
