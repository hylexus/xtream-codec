# Design

## Context

响应消息测试继承 `BaseCodecTest`，已支持独立的固定报文编码、解码和引用计数检查。四个缺测的 2019 区域/路线模型具有条件时间、限速和变长集合、名称字段，需明确集合与后续字段的边界。动机见 `proposal.md`。

## Goals / Non-Goals

验证响应类对应关系、独立编解码结果和模型已有条件分支；仅在测试复现已有协议字段边界错误时进行最小注解修复，不扩展公共 API 或协议类型。

## Decisions

- 新消息测试使用按协议字段独立计算的固定报文，分别验证编码、解码，避免往返测试掩盖成对错误。
- 用多记录和不同条件属性验证可选字段及名称长度；使用 GBK 中文名称检查字节长度和相邻记录边界。
- 通用应答别名测试覆盖继承字段编解码及全部工厂重载，使用真实请求头验证消息 ID 和流水号未对调。
- 现有测试补齐漏验字段、支持的参数解码及空集合场景；空消息使用正确消息报文，直接持有请求时在 finally 中释放缓冲区。
- 固定报文复现后，三个 2019 模型补充集合数量和名称长度表达式；增加嵌入解码保留后续字节的回归测试。两个参数示例补充参数值长度表达式，修复解码抛出负数组长度异常的问题。

## Risks / Trade-offs

- 固定报文录入错误 → 独立计算大端字段、GBK、BCD、异或校验及转义，先运行定向测试。
- 名称/集合默认消耗剩余数据 → 用后续记录和尾部字段验证边界，仅在复现后补充相应表达式。
- 样例可能只设计为编码 → 先检查字段类型的解码支持，使用合适的解码模型验证实际报文，不为测试引入生产功能。
