# 独立压测服务与接入链路设计

## Context

动机见 proposal.md。现有根构建显式注册 Java 模块并为子项目指定 `<模块名>.gradle.kts`。早期的压测配置叠加在 Debug 应用上，示例处理器仍有多参数解码开销。共享会话容器使用并发 Map，但创建、关闭及副作用没有统一原子边界。请求中的会话发布器没有缓存，TCP 消息使用并发展开。

## Goals / Non-Goals

目标是建立稳定的真实协议基线，并修复已确认的生命周期与顺序问题。默认保留现有框架调度配置，新应用使用现有 `immediate` 非阻塞处理器配置，避免第二次线程切换，同时保留分发线程上的参数解析。

本次不调整生产认证策略，不引入位置数据库、HTTP 管理端、终端号索引或新的压测平台，不替换已有部署。Debug 应用用于协议调试，常规压测由独立模块承接。接入队列大小只是新应用可配置参数，不预设既有失败由该参数导致。

## Decisions

### 独立 Gradle 应用

模块放在 `loadtest/jt/jt-808-server-loadtest`，直接依赖正式 starter。只扫描本模块的组件，关闭附件服务和逐报文日志。使用最小注册、测试鉴权和位置处理器，`0x0704` 使用正式批量位置模型解码。内存仅保留必要会话状态和固定数量的消息类别聚合计数。

### 会话原子发布与幂等关闭

使用会话键上的并发 Map 原子创建，在发布前完成计数登记。仅胜出的创建触发通知；用户监听器在 Map 原子操作之外执行，避免回调重入 Map 的更新过程。关闭只移除当前对应实例，成功移除才执行关闭副作用，旧实例不能删除新实例。创建时以及发布后复核 TCP channel 活动状态，配合现有断开回调清理，覆盖创建与断开竞态。

每个 Exchange 缓存自己的会话结果，并持有稳定可写属性集合。修复通用 Session 对传入通信时间的赋值。相同终端号查询改为选择最大通信时间，暂不维护额外索引。

发布前按实例记录尚未完成的创建通知。回调期间关闭时立即移除登记和扣减计数，关闭通知与连接清理由创建回调结束时执行。创建返回前核对登记实例，同键替换不会影响旧实例的通知。

显式创建返回有效会话，或发出携带会话 ID 和原因的 `SessionCreationRejectedException`。普通会话查询可返回空，由 `Exchange` 将断连或创建期间移除产生的这类拒绝转换为空完成，供入站处理链结束当前请求。

### TCP 顺序与缓冲区所有权

通用 TCP 接收链路保留入站缓冲区，按连接顺序且无额外预取地订阅请求处理。正常、异常、取消均释放这一份引用，并对丢弃缓冲区安装释放处理。JT/T 808 复用该接收逻辑，继续单独释放解码后的请求正文。同步解码也放在延迟执行边界内，使异常可以进入统一清理路径。

真实 UDP 协议回归进一步复现同步解码异常使接收订阅结束。为此保留每个数据报的入站引用，将其解码放到单报文延迟执行及错误恢复边界内；JT/T 808 帧切分结果在成功、解码失败和取消时均释放，同一数据报内逐帧隔离异常。UDP 并发策略不变，不做全局串行化。

关闭的 TCP 通道可以在订阅出站发布器前拒绝发送。两个 JT/T 808 应答入口使用同一资源作用域保存已编码的应答。发送器读取发布器时，以原子操作取得并接管该引用。作用域结束或监听器抛错时，同一原子操作只释放还未交给发送器的引用。

主动下发在写入前登记单值应答 sink，写入成功后读取结果。等待项按键保留，同时以实例匹配清理，键冲突由新请求失败处理。分包重组采用第 1 包的流水号，合并正文在过滤器退出时释放。附件解码回调抛错时由入口释放尚未交出的正文。

### 配置和观测

沿用 starter 的端口、空闲检查和调度属性，新应用只增加测试鉴权码、TCP backlog、汇总周期等少量配置。基准默认保留异步分发且非阻塞处理器使用 `immediate`；诊断 profile 显式开启请求日志。聚合统计区分成功、拒绝、异常、消息和位置记录，不为号码建立指标标签。日志设置单文件、归档总量和天数限制，文档说明活动文件与归档容量的口径。

压测 JAR 增加 macOS arm64 与 x86_64 kqueue 运行依赖。使用 starter 的 `prefer-native` 选择 NIO 或可用的原生传输，使用 `dedicated-accept` profile 配置一个独立的 TCP select 线程。启动日志输出实际监听通道类型和请求的 backlog，实际队列长度由操作系统决定。

TCP 接入观测复用连接就绪与解码回调。每条连接用 channel attribute 保存就绪时点和首帧状态。出站处理器在首个应答写成功时记入固定大小的延迟直方图并移除自身；关闭前未写成功的连接不产生延迟样本。百分位采用固定分桶上界，只在定期汇总时计算。既有消息统计继续提供注册、鉴权的成功和拒绝数。

## Risks / Trade-offs

- TCP 单连接串行可能降低单终端流水线吞吐 → 保留跨连接并发，回归覆盖异步顺序、错误、取消和缓冲区引用计数。
- 会话关闭与创建通知可能来自不同线程 → 原子操作保证对象和最终计数一致，监听器仍须容忍并发；不在 Map 内调用外部监听器。
- 2011/2013 相同头无法普遍自动区分 → 文档说明沿用框架检测规则，使用对应注册体测试，不声称仅凭头能识别。
- `immediate` 不适合阻塞业务 → 仅用于本模块无阻塞的固定处理器，保留异步分发，公共框架默认配置不变。
- 短跑不能证明长期无泄漏或性能收益 → 验证记录区分单元测试、真实协议短跑、构建与尚未执行的长期基准。
