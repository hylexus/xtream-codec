# 独立 JT/T 808 压测服务与终端接入修复

## Why

现有 Debug 应用会频繁调整演示功能，即使关闭日志，仍有重复消息体解析和调试依赖，难以作为稳定的性能基线。终端接入链路还存在已隔离复现的会话重复创建、重复关闭、请求上下文丢失等问题，需要通过回归测试修复。

## What Changes

- 新增 `loadtest/jt/jt-808-server-loadtest` 独立 Gradle 应用模块，直接依赖正式 JT/T 808 starter，提供可执行 JAR。
- 使用真实协议链路处理注册、鉴权、心跳、位置与批量位置上报，支持 TCP/UDP 和 2011/2013/2019；每个消息体只解析为业务所需的一种模型。
- 提供最小测试鉴权、聚合指标、容量受限日志、诊断配置及可调整的接入参数；默认保留分发调度并让非阻塞处理器沿用该线程。
- 修复会话创建和关闭的一致性、单请求会话稳定性、关闭连接禁止重建会话、属性存储与通信时间更新。
- 明确单 TCP 连接内的处理顺序，覆盖缓冲区释放与取消；按终端号查询优先选择最近通信会话。
- 修复真实协议回归检出的 UDP 同步异常终止接收问题，保持数据报与帧的错误隔离及引用释放。
- 修复断连时编码应答未交给出站发送器造成的缓冲区泄漏，覆盖注解应答和实体应答。
- 常规压测迁移到独立模块，移除 Debug 应用的临时 `loadtest` profile 和配套日志配置及说明。

## Capabilities

### New Capabilities

- `jt808-loadtest-server`：独立压测应用的协议行为、配置、观测和使用边界。
- `server-session-lifecycle`：共享会话的原子创建、幂等关闭、请求上下文及活动连接约束。
- `jt808-request-processing`：TCP 请求处理顺序、缓冲区生命周期和终端会话选择。

### Modified Capabilities

无。现有 builder 规格继续保持 API 和配置兼容。

## Impact

涉及根 Gradle 模块注册、共享 reactive server、JT/T 808 扩展、新压测模块及相关测试。沿用现有依赖管理，不增加数据库、Dashboard 或前端依赖。测试使用临时端口及隔离日志目录；性能收益须通过同环境测量确认，隔离复现不归因为既有接入失败。

显式调用 `createSession()` 时，如果 TCP 连接失效或会话在创建期间被移除，返回的 `Mono` 会发出 `SessionCreationRejectedException`。入站请求通过 `Exchange.session()` 将这类预期拒绝转换为空完成，其他异常沿原错误处理链传递。
