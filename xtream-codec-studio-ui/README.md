# Xtream Codec Studio 编辑器

多文档报文编辑器，使用 pnpm、Vite、React、TypeScript、HeroUI 3 和 Tailwind CSS 4。编解码与正式保存由 Java 后端执行，页面提供目录树、独立标签、结构和值编辑、底部运行面板与草稿恢复。

基础交互控件统一使用 HeroUI 3：导航和操作使用 Button，链接使用 Link，实体搜索与选择使用 SearchField / Select，类型搜索使用 Autocomplete，文本输入使用 TextField / Input / TextArea。示例菜单、错误提示与操作通知分别使用 Dropdown、Alert / FieldError 和 Toast。HEX 字节选择及 Trace 展开、折叠、定位也使用 HeroUI Button；JSON 编辑继续使用 CodeMirror，保留 DSL 补全能力。

## 本地开发

需要 Node.js 22.12 或更高版本，以及 pnpm。`package.json` 固定 pnpm 版本，依赖以 `pnpm-lock.yaml` 为准。

先在仓库根目录启动后端：

```bash
JAVA_HOME="$(mise where java)" ./gradlew :xtream-codec-studio-app:run --args="8765" \
  -Pxtream.frontend.build.xtream-codec-studio-ui.enabled=true
```

再在另一个终端启动前端：

```bash
cd xtream-codec-studio-ui
pnpm install --frozen-lockfile
pnpm dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。Vite 将 `/api` 请求代理到 `http://127.0.0.1:8765`，修改 React 页面后立即热更新。

后端地址可用环境变量指定，例如 `CODEC_API_TARGET=http://127.0.0.1:9000 pnpm dev`。部署在其他 API 路径时，可以在构建前设置 `VITE_CODEC_API_BASE`，默认值为 `/api/v1`。独立 Java 应用直接使用默认配置即可。

## 页面能力

- 文档标签：新建、重命名、复制、保存和关闭；模式、协议版本、输入和最近结果独立。示例会新建标签；未完成 JSON 可直接切换标签。关闭有修改的文档时可保存、放弃或取消，关闭已保存文档不会删除服务器内容。
- 标签右键菜单：保存、重命名、复制为新标签、导出完整文档，以及关闭当前、其他、右侧或全部标签。操作归属右键点击的标签；支持 Shift + F10 或菜单键打开、方向键选择和 Esc 关闭。批量关闭逐个确认未保存内容，取消后停止，保存失败时保留当前确认框与文档。
- 标签排列：右键固定或取消固定，固定标签排在左侧，标签上的图钉按钮可取消固定。拖动标签可排序，落点显示主题色指示线；固定和普通标签各自在分组内移动，也可用右键“向左 / 向右移动”或聚焦标签后按 Alt + Shift + 左右方向键。固定状态和顺序随本地草稿恢复，不影响文档的未保存状态。“关闭其他 / 右侧”保留固定标签；明确“关闭当前 / 全部”可以关闭固定标签。全部关闭后显示空工作区，提供新建与导入入口，刷新后仍保持空状态。
- 关闭范围：“关闭未固定标签”关闭全部普通标签并保留固定标签，仅剩固定标签时禁用；“关闭全部标签（含固定）”只在存在固定标签时启用，用于明确连固定标签一起关闭；没有固定标签时请使用“关闭未固定标签”。两项都逐个确认未保存内容，取消后停止后续关闭。
- 侧边栏：支持展开和收起为图标导航，并保存当前状态；顶部品牌区和底部版本区固定，中间导航、目录与示例独立滚动。“我的报文”支持嵌套目录、重命名、移动、删除和重新打开服务器文档。可拖动文件或文件夹到目标文件夹，拖动时出现“移到根目录”落点；合法目标使用主题色高亮，禁止移入自身或子目录，移动后自动保存目录位置，不提交标签中未保存的编辑。菜单“移动到…”仍可使用。
- 自由组合：新增、修改、复制和删除字段；拖动同级字段或使用上下移按钮调整顺序。拖动时源条目变淡，目标上半区/下半区显示主题色指示线及“插入到上方/下方”提示；松手按落点排序，取消拖动清理提示。递归编辑 `struct` 子字段、`array.item` 及数组元素值。
- 可视化条目：宽屏下普通字段信息、值输入和操作按钮同一行排列，收紧卡片间距及嵌套缩进；元信息紧凑显示，名称过长时可悬停查看。窄条目与多行 JSON 自动使用独立输入行。
- 编辑区滚动：桌面宽屏下结构、编码值和解码字节各自滚动，顶部编译配置及各面板操作保持可见；标签切换保留各自滚动位置，底部运行面板打开后各区随可用高度调整。宽度不超过 1000px 或高度不超过 600px 时恢复上下连续滚动。
- 面板布局：编辑区与运行区使用紧凑的连续面板，结构与输入默认按 55% / 45% 分栏；编码与解码上下排列，输入内容各自滚动，标题和操作按钮保持可见，DSL JSON 编辑器自动填满结构区。
- 调整尺寸：拖动侧栏边缘、结构/输入、编码/解码、运行面板和 HEX/字段跟踪之间的分隔线。聚焦分隔线后可用方向键微调，Shift + 方向键加大步长，Home / End 调至边界，双击或 Enter 恢复该区域默认尺寸。尺寸作为本地界面偏好保存，所有标签共用；不改变报文内容、保存状态或运行结果。窄屏自动恢复连续布局，隐藏不适用的分隔线。
- 连续拖动按浏览器刷新帧预览局部尺寸，松手时保存最终布局；按 Esc、窗口失焦或指针操作取消时恢复拖动前的尺寸，不保存未完成的调整。
- 字段配置：字段标识、名称、类型、版本、字节序、位序、长度来源与单位。表单输入和选择控件统一使用 HeroUI 3；字段类型展开显示完整候选，支持搜索并选择任意 `uN` / `iN`（1–64）。高级属性和完整字段 JSON 保留条件、分支、生成规则、表达式与扩展配置。
- DSL JSON：CodeMirror 编辑器、属性及引用补全（Ctrl + Space）、共享 JSON Schema 校验、结构导入和导出。切回可视化或执行时应用当前定义；无效定义会显示错误并保留编辑内容。切换标签不强制应用定义。
- 实体调试：搜索实体目录、载入初始值、选择协议版本并双向执行。
- 单字段试验：独立草稿中验证数值边界、长度、位序与字节序。
- 底部运行面板：执行后自动打开，随当前标签显示结果；支持拖动高度、聚焦分隔线后用上下键调整、折叠和最大化。显示消费 bit/byte、剩余输入、校验和匹配状态、字段错误与部分 Trace；支持逐节点展开和折叠，点击 Trace 高亮字节和位，点击字节定位相关字段并展开其祖先节点。HEX 按 256 字节分页。标签切换保留选择与折叠；输入变化后显示旧结果标记。请求归属发起标签，回包不会覆盖另一个标签。
- 保存与恢复：Ctrl/⌘+S 保存到后端，首次选择名称和目录。IndexedDB 自动备份打开标签、未完成原文和最近结果；首次升级迁移旧 localStorage 草稿。保存失败或冲突保留原文，保存期间的新编辑仍标为未保存。文档菜单支持完整文档和工作区备份的导入导出，字段区继续支持仅 Schema 导入导出。
- 明暗主题和九种主题色保存到当前浏览器。顶部调色板入口用 3×3 九宫格提供九种主题色，仅显示色块与选中标记，支持键盘选择，影响主要按钮、导航选中态、焦点、编辑器选区及浏览器标签页图标；字段类型与成功、警告等状态颜色保持独立。整数超过 JavaScript 安全范围时用十进制字符串传递，避免 `u64` 精度损失。

复杂的 `choice`、TLV、map、pair 和扩展值可以在 JSON 编辑器中填写。工作台共用 core 的 JSON Schema，不维护另一份 DSL 定义；字符串表达式和扩展是否可执行取决于宿主后端注册的能力。

## 检查与生产构建

```bash
pnpm test
pnpm build
```

`build` 先执行 TypeScript 与补全脚本检查，然后将 Vite 产物输出到 `dist/`。独立 Java 应用与 Dashboard 等模块统一使用 `xtream-codec-frontend-build-plugin` 和 `xtreamCodecFrontendBuild` 扩展。插件负责安装锁定的依赖、执行前端测试与构建，再将产物复制到应用的 `src/main/resources/ui/`，随 `processResources` 打包。该目录已被 Git 忽略，每次复制前会清理旧产物；发布后的应用运行时只需要 Java。

构建开关为 `xtream.frontend.build.xtream-codec-studio-ui.enabled`，当前仓库配置为 `false`。首次启动和静态资源测试必须显式设为 `true`；已有打包资源时可以关闭前端构建：

```bash
./gradlew :xtream-codec-studio-app:build \
  -Pxtream.frontend.build.xtream-codec-studio-ui.enabled=false
```

关闭开关会跳过安装、测试、构建和复制，沿用应用资源目录中已生成的 UI。首次检出仓库时需要开启构建。pnpm 和满足版本要求的 Node.js 应能从 PATH 中访问。

插件在根项目注册 `xtreamCodecFrontendBuild__xtream-codec-studio-ui` 构建任务，在 Java 调试模块注册 `copyFrontendDist`。增量构建跟踪前端源码、package.json、锁文件、入口 HTML、Vite 与 TypeScript 配置、pnpm workspace、前端测试和 core 共享 JSON Schema；这些输入没有变化时会跳过构建。

## 验收样例

| 样例                              | 预期编码 HEX                                                                                                           | 检查重点                                                                    |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 位字段与嵌套集合                  | `b10702011234025678`                                                                                                   | 3 + 5 bit、长度回填、嵌套数组、同一字节的位范围                             |
| 文本与字节序                      | `34120658747265616d13912345678903aabbcc`                                                                               | 小端、UTF-8、BCD、前置字节长度                                              |
| 自动生成与校验和                  | `7e03102030037e`                                                                                                       | 固定边界、元素计数、XOR8 区间校验和                                         |
| 808 · 0200 位置汇报（2013）       | `7e0200002601391234432900000000006f0000001601dc9a0707456246007b004200032501292233440202006401040000000c007e`           | 同一 Schema 选择 2013 版、6 字节终端号、自动回填体长度、BCD 时间、TLV、XOR8 |
| 808 · 0200 位置汇报（2019，默认） | `7e02004026010000000001391234432900000000006f0000001601dc9a0707456246007b004200032501292233440202006401040000000c417e` | 同一 Schema 选择 2019 版、协议版本号、10 字节终端 ID、BCD 左侧补零          |
| 单字段初始草稿                    | `ffffffffffffffff`                                                                                                     | `u64` 最大值 `18446744073709551615`                                         |

每个样例都可编码后直接解码。校验和样例将 checksum 字节从 `03` 改成 `01` 时，应正常展示解码结果与“不匹配”状态。嵌套样例将输入截断为 `b10702` 时，应展示字段错误和已经完成的 Trace。

0200 样例通过同一 Schema 支持 JT/T 808 2013 和 2019，载入时默认选择 2019。在顶部“目标协议版本”填入 `2013` 或 `2019` 后编码，即可得到对应版本的 HEX；解码时需选择与输入报文一致的目标版本，版本不会由 HEX 自动推断，也不要留空。2013 分支的版本标识固定为 0，终端号占 6 字节，不写协议版本号；2019 分支的版本标识固定为 1，增加协议版本号，终端 ID 占 10 字节。预置输入共用 `terminalId = "013912344329"`，2019 分支通过 `options: { "padByte": 0, "padSide": "left" }` 左侧补零写成 `"00000000013912344329"`，解码保留完整终端 ID。两版消息体均为 38 字节，完整报文分别为 53、58 字节，校验码分别为 `00`、`41`。

消息体、附加信息和 2019 版参考字节来自仓库的 `0200-2019.json` / `Jt808DynamicDslTest`。消息体属性按位拆成保留位、版本标识、分包标识、加密方式和自动回填的体长度；编码时无需填写消息 ID、体长度、版本标识、协议版本号或校验码。输入经纬度采用协议整数单位（10⁻⁶ 度），速度、里程和油量分别以 0.1 km/h、0.1 km 和 0.1 L 为单位；BCD 时间保留数字串。TLV 项以 `{ "key": 2, "value": 100 }` 的格式编辑。

样例包含两侧 `7e`，XOR8 范围为消息 ID 到消息体末尾，不包含帧标记。当前不处理转义；预置内容不含需要转义的字节，编辑后出现 `7d` / `7e` 时仍展示未转义的编码结果。

编辑方面，重点检查数组元素结构中的字段改名、复制、删除与新增是否同步所有已有元素值；标签切换及刷新后是否保留原文与运行快照；完整 JSON 与可视化之间切换是否保留高级属性。正式存储配置和 HTTP 合同见 [WORKSPACE.md](../xtream-codec-studio-app/WORKSPACE.md)。

## 后续接入 Dashboard

`src/api.ts` 封装 HTTP 合同，`src/workspace.ts` 负责文档合同、保存基线和运行归属，`src/draft-store.ts` 负责 IndexedDB 恢复，`src/model.ts` 负责结构和值的更新。编辑区、目录树、运行面板、字段树、字段弹窗、值编辑器、JSON 编辑器和 Trace 查看器独立放在 `src/components/`。接入 Dashboard 时可复用这些模块，用 Dashboard 的导航、主题入口和 HTTP 客户端替换 Studio 外壳。

后端合同与宿主接入方式见 [独立应用文档](../xtream-codec-studio-app/README.md) 和 [INTEGRATION.md](../xtream-codec-studio-app/INTEGRATION.md)。
