# Xtream Codec Studio 编辑器

多文档报文编辑器，使用 pnpm、Vite、React、TypeScript、HeroUI 3 和 Tailwind CSS 4。编解码与正式保存由 Java 后端执行，页面提供目录树、独立标签、结构和值编辑、底部运行面板与草稿恢复。

基础交互控件统一使用 HeroUI 3：导航和操作使用 Button，链接使用 Link，实体搜索与选择使用 SearchField / Select，类型搜索使用 Autocomplete，文本输入使用 TextField / Input / TextArea。示例菜单、错误提示与操作通知分别使用 Dropdown、Alert / FieldError 和 Toast。HEX 字节选择及 Trace 展开、折叠、定位也使用 HeroUI Button；JSON 和解码 HEX 共用 CodeMirror 编辑器与主题，JSON 保留 DSL 补全能力。

## 本地开发

需要 Node.js 22.12 或更高版本，以及 pnpm。`package.json` 固定 pnpm 版本，依赖以 `pnpm-lock.yaml` 为准。

先在仓库根目录启动后端：

```bash
JAVA_HOME="$(mise where java)" ./gradlew :xtream-codec-studio-app:run --args="8765" \
  -Pxtream.frontend.build.xtream-codec-studio-ui.enabled=true
```

再在另一个终端启动前端：

```bash
cd xtream-codec-studio-ui
pnpm install --frozen-lockfile
pnpm dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。Vite 将 `/api` 请求代理到 `http://127.0.0.1:8765`，修改 React 页面后立即热更新。

后端地址可用环境变量指定，例如 `CODEC_API_TARGET=http://127.0.0.1:9000 pnpm dev`。部署在其他 API 路径时，可以在构建前设置 `VITE_CODEC_API_BASE`，默认值为 `/api/v1`。独立 Java 应用直接使用默认配置即可。

支持通过服务器 IP 或域名的 HTTP 地址访问。标签 ID 优先使用原生 `crypto.randomUUID()`，不可用时通过 `crypto.getRandomValues()` 生成 UUID v4，因此首次草稿恢复、新建和重新打开报文不依赖安全上下文，已有草稿格式保持兼容。

## 页面能力

- 报文时间：文档工具栏的“…”菜单中选择“报文信息”，可查看服务器创建时间和最后更新时间，目录名称悬停提示也包含时间。首次保存时两者相同，成功保存、重命名或移动后更新最后更新时间，本地编辑和失败保存不改变服务器时间。旧报文没有可靠创建时间时显示“未记录”，未保存报文显示“尚未保存”；工作区导入生成新报文，其时间从此次导入开始记录。
- 工作区状态：左侧“我的报文”标题旁显示工作区条目数（含目录），工作区不可用时显示“离线”。保存快捷键见保存按钮的悬浮提示；报文标签的圆点表示有未保存更改。
- 文档标签：新建、重命名、复制、保存和关闭；模式、协议版本、输入和最近结果独立。示例会新建标签；未完成 JSON 可直接切换标签。关闭有修改的文档时可保存、放弃或取消，关闭已保存文档不会删除服务器内容。
- 标签右键菜单：保存、重命名、复制为新标签、导出完整文档，以及关闭当前、其他、右侧或全部标签。操作归属右键点击的标签；支持 Shift + F10 或菜单键打开、方向键选择和 Esc 关闭。批量关闭逐个确认未保存内容，取消后停止，保存失败时保留当前确认框与文档。
- 标签排列：右键固定或取消固定，固定标签排在左侧，标签上的图钉按钮可取消固定。拖动标签可排序，落点显示主题色指示线；固定和普通标签各自在分组内移动，也可用右键“向左 / 向右移动”或聚焦标签后按 Alt + Shift + 左右方向键。固定状态和顺序随本地草稿恢复，不影响文档的未保存状态。“关闭其他 / 右侧”保留固定标签；明确“关闭当前 / 全部”可以关闭固定标签。全部关闭后显示空工作区，提供新建与导入入口，刷新后仍保持空状态。
- 关闭范围：“关闭未固定标签”关闭全部普通标签并保留固定标签，仅剩固定标签时禁用；“关闭全部标签（含固定）”只在存在固定标签时启用，用于明确连固定标签一起关闭；没有固定标签时请使用“关闭未固定标签”。两项都逐个确认未保存内容，取消后停止后续关闭。
- 侧边栏：支持展开和收起为图标导航，并保存当前状态；顶部品牌区和底部版本区固定，中间导航、目录与示例独立滚动。“我的报文”支持嵌套目录、重命名、移动、删除和重新打开服务器文档。可拖动文件或文件夹到目标文件夹，拖动时出现“移到根目录”落点；合法目标使用主题色高亮，禁止移入自身或子目录，移动后自动保存目录位置，不提交标签中未保存的编辑。菜单“移动到…”仍可使用。
- 自由组合：新增、修改、复制和删除字段；拖动同级字段或使用上下移按钮调整顺序。拖动时源条目变淡，目标上半区/下半区显示主题色指示线及“插入到上方/下方”提示；松手按落点排序，取消拖动清理提示。递归编辑 `struct` 子字段、`array.item` 及数组元素值。
- 可视化条目：宽屏下普通字段信息、值输入和操作按钮同一行排列，收紧卡片间距及嵌套缩进；元信息紧凑显示，名称过长时可悬停查看。窄条目与多行 JSON 自动使用独立输入行。
- 长度前缀：摘要分别显示“前缀占 8 位（1 字节）”与“值表示字节数”。配置弹窗区分前缀占用位数与前缀值表示的字节数、位数或元素数量，并提供对应示例；例如前缀值为 3 时，后续内容占 3 字节。`prefixBits: 8` 表示前缀自身占 8 位，内容长度由前缀值决定。
- 编辑区滚动：桌面宽屏下结构、编码值和解码字节各自滚动，顶部编译配置及各面板操作保持可见；标签切换保留各自滚动位置，底部运行面板打开后各区随可用高度调整。宽度不超过 1000px 或高度不超过 600px 时恢复上下连续滚动。
- 面板布局：结构、编码、解码与运行区使用 IDEA 风格的 8px 圆角面板，区域之间保留 8px 窄间距；结构与输入默认按 55% / 45% 分栏，编码与解码上下排列，输入内容各自滚动。编码与解码按钮固定在各自标题栏右侧，解码字节数紧邻标题，输入内容填满剩余空间；DSL JSON 编辑器自动填满结构区。
- 调整尺寸：拖动侧栏边缘、结构/输入、编码/解码、运行面板和 HEX/字段跟踪之间的分隔线。把手默认隐藏，悬停、键盘聚焦或拖动时显示。聚焦分隔线后可用方向键微调，Shift + 方向键加大步长，Home / End 调至边界，双击或 Enter 恢复该区域默认尺寸。尺寸作为本地界面偏好保存，所有标签共用；不改变报文内容、保存状态或运行结果。窄屏自动恢复连续布局，隐藏不适用的分隔线。
- 连续拖动按浏览器刷新帧预览局部尺寸，松手时保存最终布局；按 Esc、窗口失焦或指针操作取消时恢复拖动前的尺寸，不保存未完成的调整。
- 字段配置：字段标识、名称、类型、版本、字节序、位序、长度来源与单位。表单输入和选择控件统一使用 HeroUI 3；字段类型展开显示完整候选，支持搜索并选择任意 `uN` / `iN`（1–64）。高级属性和完整字段 JSON 保留条件、分支、生成规则、表达式与扩展配置。
- DSL JSON：CodeMirror 编辑器、属性及引用补全（Ctrl + Space）、共享 JSON Schema 校验、结构导入和导出。行号栏与编辑区共用中性底色，明暗主题下保留当前行和折叠标识，结果的只读 JSON 使用相同样式。切回可视化或执行时应用当前定义；无效定义会显示错误并保留编辑内容。切换标签不强制应用定义。
- 解码 HEX：使用相同主题的 CodeMirror，显示行号、当前行和选区，长报文不自动折行，通过输入区内部横向滚动查看；粘贴的空白和显式换行保留，字节数统计及执行时的 HEX 规范化沿用原逻辑。HEX 不启用 JSON 补全或括号配对，标题与解码按钮固定，输入区随面板尺寸变化。
- 实体调试：搜索实体目录、载入初始值、选择协议版本并双向执行。
- 单字段试验：独立草稿中验证数值边界、长度、位序与字节序。
- 底部运行面板：执行后自动打开，随当前标签显示结果；支持拖动高度、聚焦分隔线后用上下键调整、折叠和最大化。左上角使用 macOS 风格的红、黄、绿圆点，分别对应关闭、折叠、最大化或还原；悬停或键盘聚焦显示操作图标，关闭或折叠后可从工具栏重新打开，结果保留。显示消费 bit/byte、剩余输入、校验和匹配状态、字段错误与部分 Trace；支持逐节点展开和折叠，点击 Trace 高亮字节和位，点击字节定位相关字段、展开其祖先并将节点平滑滚动到 FieldTrace 可视区，避开固定表头；节点已可见时保持位置，再次点击相同字节可重新定位，仅调整 Trace 纵向滚动。连续点击以最新选择为准，系统偏好减少动态效果时立即定位。HEX 按 256 字节分页。标签切换保留选择与折叠；输入变化后显示旧结果标记。请求归属发起标签，回包不会覆盖另一个标签。
- 结果布局：执行状态、消费统计、校验和与操作共用紧凑结果栏，校验和展示字段、实际值、期望值和匹配状态，悬停查看算法及完整说明；窄容器自动换行，结果栏最多占可用高度的 35% 且不超过 120px，内容超出时滚动。HEX 和字段跟踪填满剩余高度，固定分区标题并独立滚动；字节预览随 HEX 滚动，节点详情随 Trace 滚动。窄屏上下排列，高度不足时恢复左右排列；小高度自动收紧标题和标签间距。诊断区限制高度，字段值和完整响应编辑器自动填满剩余空间。
- 分区边界：结构、编码、解码与运行面板使用中性细边框、圆角和窄间距，HEX/Trace 保留低对比细边框与圆角，标题采用淡分隔，明暗主题分别适配。分隔线保留原有拖动区域，焦点与拖动仍使用主题色，字段内部保留较淡的分隔与层级引导，窄屏上下排列仍有圆角与间距。
- HEX 坐标：列坐标下方、行偏移右侧使用 Dashboard 风格的中性细分隔线，坐标标签带淡边框；字节格固定为 32px 正方形，每行 16 字节，列坐标与内容对齐。调整面板宽度不会拉伸格子，窄面板在 HEX 内横向滚动，最后一行保持原列位置。
- 字节预览：HEX 下方始终展开，保留字段路径与字节范围；Bit、编码、数值使用独立的中性边框圆角卡片，按 HEX 区实际宽度并排或换行。bit 格子固定为 24px 宽；编码显示 ASCII、UTF-8、GBK、GB2312、BCD，原始字节数值显示 HEX、BIN 和有符号/无符号大小端整数。原始字节预览使用当前最多八字节的片段，分段同步更新；整数保留 64 位精度，BCD 保留前导零。非字节对齐字段继续高亮对应位，并提示原始字节预览包含完整边界字节。
- 字段值与原始字节：数值卡片顶部显示 Trace 实际字段值、类型及完整字段位宽，整数附带 HEX/BIN，有符号负数按字段位宽显示补码；字段值不受八字节分段影响。下方“原始字节数值”和编码卡片使用当前片段的完整字节并明确标注范围。例如 `versionFlag: u1` 显示字段值 `1`，覆盖它的原始字节 `0x40` 仍解释为 `64`。旧快照可用摘要回退，失败或未完成字段不会生成成功的整数预览。
- 前置长度：动态字段的 Trace 在对应字段之前增加同级的金色“字段名 前置长度”节点，可以从 HEX 单独定位前缀并查看长度值。选择内容字段时，HEX 高亮和字节预览均只显示内容，标注“不含长度前缀”；选择前缀节点时仅高亮长度字节，空内容不高亮前缀或相邻字段。旧运行结果沿用原结构与范围，重新执行后获得内容范围与同级长度节点。
- Trace 树使用节点、类型、位范围和值四列，类型优先显示后端实际返回的 DSL 声明类型或简短 Java 类型，悬停可查看节点类别及完整类型；旧结果缺少类型时显示节点类别。节点用单行字段路径与内联说明展示，仅名称按层级缩进；路径、说明和值截断时可悬停查看全文。固定表头随树纵向滚动保持可见，窄面板保持四列单行并在树内横向滚动，表头和节点一起滚动以保持对齐。折叠按钮与字段选择独立操作，保留 HEX 定位和键盘交互。
- Trace 类型颜色：显示类型名称经稳定 hash 映射到蓝、紫、绿、金、青色板，同类型的圆点、标签和节点详情始终同色，颜色不受节点职责、路径或出现顺序影响；例如普通字段、Tag 和 Length 的 `u8` 使用相同颜色。明暗主题使用对应色值，主操作主题色只影响选中背景；ERROR/FAILED 节点统一使用红色，正常类型不使用错误红色。固定色板允许不同类型使用相同颜色，完整类型仍由文字和悬停提示识别。
- TLV 条目按输入数组或线上顺序展示，`[0]`、`[1]` 是条目序号，旁边注明 Tag 值；每个条目下展开 Tag、Length、Value，分别定位自己的字节，条目节点定位整个 TLV。重复 Tag 保留为独立条目，未知 Value 显示为 `hex`，已知 Value 保留声明类型、说明和嵌套字段。map 同样显示 Key、Length、Value，pair 显示 Key、Value。已有运行快照重新执行后获得这些节点。
- 保存与恢复：Ctrl/⌘+S 保存到后端，首次选择名称和目录。IndexedDB 自动备份打开标签、未完成原文和最近结果；首次升级迁移旧 localStorage 草稿。保存失败或冲突保留原文，保存期间的新编辑仍标为未保存。文档菜单支持完整文档和工作区备份的导入导出，字段区继续支持仅 Schema 导入导出。
- 浏览器页面草稿：每个浏览器标签页独立备份自己的报文标签、原文、固定及排序状态和运行快照，切到后台不会覆盖其他页面。刷新恢复本页；浏览器复制标签页以来源最近已备份的内容创建独立副本。没有本页恢复记录的新访问复制站点最近成功备份；没有任何草稿时使用默认工作区。编辑器内的报文标签仍一起恢复，主题和面板布局继续作为站点偏好共享。
- 草稿升级及失败：兼容原共享 IndexedDB 和旧 localStorage 草稿，保留原始迁移来源。存储禁用、配额不足或本页记录损坏时明确提示，仍可在内存中编辑，不会回退到共享可写草稿或静默采用其他页面内容。恢复保证针对已成功备份的内容；旧版页面不自动读取新版独立草稿。
- 保存冲突：同一服务器报文被其他页面修改后，保存会展示服务器名称、版本和更新时间。可选择“使用服务器版本”放弃本地未保存修改，或“用本地版本覆盖服务器”替换服务器内容与运行结果，保留服务器名称和目录；取消则继续保留本地编辑。覆盖仍校验已确认版本，再次冲突需要重新选择，不自动合并或重试。读取、覆盖失败或报文被删除时保留原文和保存基线，不自动重建服务器报文。
- 冲突与关闭：快捷键、工具栏及保存后关闭使用同一处理方式。关闭队列等待冲突处理成功且没有后续新编辑后才继续；取消或失败保留当前与后续报文。采用服务器内容后，原本地输入发起的迟到运行结果不会写回新文档；本地覆盖期间产生的新编辑和运行结果继续标记为未保存。
- 明暗主题和九种主题色保存到当前浏览器。顶部调色板入口用 3×3 九宫格提供九种主题色，仅显示色块与选中标记，支持键盘选择，影响主要按钮、导航选中态、焦点、编辑器选区及浏览器标签页图标；字段类型与成功、警告等状态颜色保持独立。整数超过 JavaScript 安全范围时用十进制字符串传递，避免 `u64` 精度损失。
- 配色沿用 Dashboard 的中性黑灰/白灰底色，青绿表示普通字段和成功状态，蓝紫表示容器，金色表示前置长度，红色表示错误。首次打开使用蓝色主题；浏览器中已保存的主题色继续保留，编辑器与控件随明暗主题统一切换。

复杂的 `choice`、TLV、map、pair 和扩展值可以在 JSON 编辑器中填写。工作台共用 core 的 JSON Schema，不维护另一份 DSL 定义；字符串表达式和扩展是否可执行取决于宿主后端注册的能力。

## 检查与生产构建

```bash
pnpm test
pnpm build
```

原生 IndexedDB 和多页面回归使用系统 Chrome 及单独准备的 Playwright。启动本地 Vite 后，将 `STUDIO_PLAYWRIGHT_MODULE` 指向 Playwright 的 `index.mjs`，运行：

```bash
STUDIO_PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node --test test/browser/*.mjs
```

默认访问 `http://127.0.0.1:5173`，可通过 `STUDIO_UI_URL` 指定其他测试前端。测试使用隔离浏览器上下文，草稿与冲突测试拦截 API 请求，不写入当前开发后端。

`live-workspace.mjs` 默认跳过。真实接口验收需要先以独立临时数据目录启动空后端，再用 `STUDIO_TEMP_API_URL=http://127.0.0.1:18765` 运行该脚本；脚本只接受本机非 8765 端口，并在创建测试报文前检查工作区为空。浏览器请求会转发到该临时后端，验证双页面保存、双向选择、再次冲突、独立刷新和删除失败；不能指定真实用户工作区。

`build` 先执行 TypeScript 与补全脚本检查，然后将 Vite 产物输出到 `dist/`。独立 Java 应用与 Dashboard 等模块统一使用 `xtream-codec-frontend-build-plugin` 和 `xtreamCodecFrontendBuild` 扩展。插件负责安装锁定的依赖、执行前端测试与构建，再将产物复制到应用的 `src/main/resources/ui/`，随 `processResources` 打包。该目录已被 Git 忽略，每次复制前会清理旧产物；发布后的应用运行时只需要 Java。

构建开关为 `xtream.frontend.build.xtream-codec-studio-ui.enabled`，当前仓库配置为 `false`。首次启动和静态资源测试必须显式设为 `true`；已有打包资源时可以关闭前端构建：

```bash
./gradlew :xtream-codec-studio-app:build \
  -Pxtream.frontend.build.xtream-codec-studio-ui.enabled=false
```

关闭开关会跳过安装、测试、构建和复制，沿用应用资源目录中已生成的 UI。首次检出仓库时需要开启构建。pnpm 和满足版本要求的 Node.js 应能从 PATH 中访问。

插件在根项目注册 `xtreamCodecFrontendBuild__xtream-codec-studio-ui` 构建任务，在 Java 调试模块注册 `copyFrontendDist`。增量构建跟踪前端源码、package.json、锁文件、入口 HTML、Vite 与 TypeScript 配置、pnpm workspace、前端测试和 core 共享 JSON Schema；这些输入没有变化时会跳过构建。

## 验收样例

| 样例                              | 预期编码 HEX                                                                                                           | 检查重点                                                                    |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 位字段与嵌套集合                  | `b10702011234025678`                                                                                                   | 3 + 5 bit、长度回填、嵌套数组、同一字节的位范围                             |
| 文本与字节序                      | `34120658747265616d13912345678903aabbcc`                                                                               | 小端、UTF-8、BCD、前置字节长度                                              |
| 自动生成与校验和                  | `7e03102030037e`                                                                                                       | 固定边界、元素计数、XOR8 区间校验和                                         |
| 808 · 0200 位置汇报（2013）       | `7e0200002601391234432900000000006f0000001601dc9a0707456246007b004200032501292233440202006401040000000c007e`           | 同一 Schema 选择 2013 版、6 字节终端号、自动回填体长度、BCD 时间、TLV、XOR8 |
| 808 · 0200 位置汇报（2019，默认） | `7e02004026010000000001391234432900000000006f0000001601dc9a0707456246007b004200032501292233440202006401040000000c417e` | 同一 Schema 选择 2019 版、协议版本号、10 字节终端 ID、BCD 左侧补零          |
| 单字段初始草稿                    | `ffffffffffffffff`                                                                                                     | `u64` 最大值 `18446744073709551615`                                         |

每个样例都可编码后直接解码。校验和样例将 checksum 字节从 `03` 改成 `01` 时，应正常展示解码结果与“不匹配”状态。嵌套样例将输入截断为 `b10702` 时，应展示字段错误和已经完成的 Trace。

0200 样例通过同一 Schema 支持 JT/T 808 2013 和 2019，载入时默认选择 2019。在顶部“目标协议版本”填入 `2013` 或 `2019` 后编码，即可得到对应版本的 HEX；解码时需选择与输入报文一致的目标版本，版本不会由 HEX 自动推断，也不要留空。2013 分支的版本标识固定为 0，终端号占 6 字节，不写协议版本号；2019 分支的版本标识固定为 1，增加协议版本号，终端 ID 占 10 字节。预置输入共用 `terminalId = "013912344329"`，2019 分支通过 `options: { "padByte": 0, "padSide": "left" }` 左侧补零写成 `"00000000013912344329"`，解码保留完整终端 ID。两版消息体均为 38 字节，完整报文分别为 53、58 字节，校验码分别为 `00`、`41`。

消息体、附加信息和 2019 版参考字节来自仓库的 `0200-2019.json` / `Jt808DynamicDslTest`。消息体属性按位拆成保留位、版本标识、分包标识、加密方式和自动回填的体长度；编码时无需填写消息 ID、体长度、版本标识、协议版本号或校验码。输入经纬度采用协议整数单位（10⁻⁶ 度），速度、里程和油量分别以 0.1 km/h、0.1 km 和 0.1 L 为单位；BCD 时间保留数字串。TLV 项以 `{ "key": 2, "value": 100 }` 的格式编辑。

样例包含两侧 `7e`，XOR8 范围为消息 ID 到消息体末尾，不包含帧标记。当前不处理转义；预置内容不含需要转义的字节，编辑后出现 `7d` / `7e` 时仍展示未转义的编码结果。

编辑方面，重点检查数组元素结构中的字段改名、复制、删除与新增是否同步所有已有元素值；标签切换及刷新后是否保留原文与运行快照；完整 JSON 与可视化之间切换是否保留高级属性。正式存储配置和 HTTP 合同见 [WORKSPACE.md](../xtream-codec-studio-app/WORKSPACE.md)。
